# smart-voca 웹 서비스 — 구현 계획

**파일 위치**: `docs/web/작업계획_261104_웹 구현 계획 v0.5.md`
**작성일**: 2026-11-04
**버전**: v0.5 (M3 구현 결과 반영)
**설명**: 1~6단계 설계를 실제 코드로 옮기는 순서, 파일 구조, 기존 코드 재사용 범위, 테스트 구성, 마일스톤을 정리한 7단계 계획 문서

---

## 1. 전제

- 설계 문서 6종 (결정 기록, 데이터 모델, 인증·보안, API, 화면, 배포·운영)이 기준이다. 충돌하면 결정 기록 → 나머지 순으로 따른다.
- 기존 데스크톱 앱의 핵심 로직 59개 테스트는 **계속 통과해야 한다**. 웹 전환 중에도 `src/core/`의 동작은 바꾸지 않는다.
- 한 마일스톤이 끝날 때마다 실행 가능한 상태이고 테스트가 통과해야 한다.
- 일정은 정하지 않는다. 마일스톤 순서만 정하고, 진행 속도는 사용자와 맞춘다.

## 2. 기존 코드 재사용 분석

### 2.1 재사용 가능 (수정 없이 또는 최소 수정)

| 모듈 | 역할 | 웹에서의 사용 |
|------|------|---------------|
| `src/core/day_planner.py` | 일차 진도 생성 | 그대로 호출. 입력은 `Word` 목록과 단어 이름을 키로 한 `StudyRecord` dict이며, DB에서 읽어 만든다 |
| `src/core/quiz_builder.py` | 시험 문항·보기 생성 | 그대로 호출. 결과 `QuizItem`은 DB에 저장하고 정답 필드는 응답에서 뺀다 |
| `src/core/answer_checker.py` | 정답 판정 | 그대로 호출 (서버 채점) |
| `src/core/word_service.py` | 단어 검증, 검색, 수정·삭제 규칙 | `split_meanings`와 빈 값 검사만 호출한다. 중복 검사와 검색은 같은 규칙을 SQL로 구현한다 (D-IMP09). 삭제·이름 변경은 DB 규칙(소프트 삭제, `word_id`)에 맞게 서비스 계층에서 처리 |
| `src/models.py` | 데이터 클래스 | 그대로 사용 |
| `src/config.py` | 기본값, 라벨 대응표 | 기본값·라벨은 그대로. 파일 경로 상수는 웹에서 쓰지 않음 |

### 2.2 재사용하지 않음 (웹 전환 후 제거 대상)

| 모듈 | 이유 |
|------|------|
| `src/gui/` 전체 | tkinter 화면. 웹 화면으로 대체 (결정 D-W05) |
| `src/main.py` | 데스크톱 진입점 |
| `*_repository.py` (CSV 저장) | 웹은 DB 저장. 레거시 CSV 이관 도구는 제외되어 현재 쓰임이 없음 (§11). 제거 시점은 M11에서 함께 정함 |
| `src/core/file_utils.py` | 원자적 CSV 쓰기. 웹에서는 쓰지 않음 |

### 2.3 주의할 결합 지점

- **키가 단어 문자열이다.** 기존 `records: Dict[str, StudyRecord]`, `DayPlanItem.word`는 단어 이름으로 연결된다. 웹은 `word_id`로 연결한다 (데이터 모델 D-W08).
  - 대응: **core는 텍스트 키를 그대로 쓰고**, 웹 서비스 계층에서 DB 행 → 메모리 객체로 바꾼 뒤 core를 호출하고, 결과를 다시 `word_id`로 바꿔 저장한다. core를 고치지 않는 것이 이 계획의 핵심 선택이다 (D-IMP02).
  - 단어 이름이 같은 회원 안에서 유일해야 한다 (`word_key` 중복 금지, D-24). 그래야 텍스트 키가 안전하다.
- **`Word`에 DB id가 없다.** 매핑용으로 `Word`를 바꾸지 않고, 서비스 계층에서 `{word_text: word_id}` 사전을 따로 만든다.
- **`QuizItem`에 정답이 들어 있다.** API 응답 변환 함수에서 정답 필드를 항상 뺀다 (API 설계 D-API02).
- **`config.py`는 경로만 정의하고 폴더를 만들지 않는다** (코드 확인 완료). 폴더 생성은 저장소 코드(`file_utils`, repository)가 한다. 웹은 CSV 경로 상수를 쓰지 않으므로 영향이 없다.
- **`quiz_builder`는 `ValueError`를 던진다.** 객관식 보기가 4개 미만이거나 단어가 부족하면 발생한다. 웹 서비스 계층에서 `422 TEST_NOT_POSSIBLE`로 바꾼다.

### 2.4 `models.py`의 `from models import ...` 방식

- 현재 import는 `src/`가 경로에 있다고 가정한다 (`from models import Word`). 웹 패키지는 `src/web/` 아래에 두고, 실행 진입점에서 `src/`를 경로에 넣는다.
- 패키지 구조를 `src.core`처럼 바꾸는 것은 하지 않는다 (기존 import 전체를 바꾸는 위험을 피함).

## 4. 기술 선택 (설계 문서 결정 반영)

| 항목 | 선택 | 근거 |
|------|------|------|
| 웹 프레임워크 | FastAPI | D-W01 |
| 템플릿 | Jinja2 | D-UI05 |
| ORM | SQLAlchemy | 데이터 모델 D-W02 (SQLite → PostgreSQL 전환 용이) |
| 마이그레이션 | Alembic | 배포 설계 §3.3 |
| 데이터 검증 | pydantic | FastAPI 기본 (요청·응답 형식) |
| 환경변수 읽기 | pydantic-settings | `.env`와 환경변수를 타입 검사와 함께 읽음 (D-IMP07) |
| 폼·파일 업로드 | python-multipart | FastAPI가 폼과 CSV 업로드를 읽을 때 필요 |
| 비밀번호 해시 | argon2-cffi | 인증 설계 D-A03 |
| 테스트 | 기존 `unittest` + FastAPI `TestClient` (httpx) | 기존 테스트 체계 유지 (D-IMP01) |
| 서버 실행 | uvicorn | FastAPI 표준 |
| 소셜 로그인 | 제공자 어댑터 직접 구현 (OAuth 2.0 + PKCE) | 제공자 두 곳뿐이라 전용 라이브러리 없이도 단순함. 필요하면 나중에 교체 (D-IMP04) |

- 외부 패키지는 버전을 고정한다. 운영용은 `requirements.txt`, 개발·테스트용은 `requirements-dev.txt`에 둔다. `httpx`는 지금은 테스트에만 쓰므로 개발용에 두고, M8에서 운영용으로 옮긴다.
- 설치는 프로젝트의 가상환경 `.venv`에 한다 (D-IMP05).

## 6. 테스트 구성

| 층 | 대상 | 방법 |
|----|------|------|
| 기존 단위 테스트 | `src/core/` 등 (59개) | 웹 테스트와 같은 명령으로 함께 실행 |
| 웹 API 테스트 | 엔드포인트 응답과 상태 코드 | FastAPI `TestClient`, 임시 SQLite DB |
| 권한 격리 테스트 | 회원 A의 자원을 회원 B가 못 봄 | 회원 두 명을 만들고 모든 자원 ID에 대해 404 확인 |
| 보안 테스트 | CSRF 누락 403, 잠금, 수식 주입, 파일 크기, 시험 정답 미노출 | 개별 테스트 |
| 화면 테스트 | 페이지가 뜨고 핵심 요소가 보임 | TestClient로 HTML 확인. 실제 클릭은 수동 점검 |
| 브라우저 점검 | 암기·시험 키보드 동작, 휴대폰 화면 | 수동 점검 목록 작성 (자동화는 나중에 검토) |

- 테스트는 `data/`를 건드리지 않는다. 웹 테스트는 임시 DB를 쓴다 (CLAUDE.md 특화 메모 "실행 중 데이터 변경").
- 실행 명령은 프로젝트 루트에서 `.venv\Scripts\python -m unittest discover -s tests`다. 시스템 Python에는 웹 패키지가 없어 `py -3`으로 실행하면 웹 테스트가 import 오류로 실패한다 (D-IMP05).
- `tests/web_tests/`에는 `__init__.py`를 둔다. `unittest discover`가 하위 폴더를 찾으려면 필요하다. 폴더 이름은 `web`으로 하지 않는다 (D-IMP06).
- 공용 도우미는 `tests/web_tests/support.py`에 두고 테스트에서 직접 import한다. `conftest.py`는 pytest만 자동으로 읽으므로 쓰지 않는다 (D-IMP01).
- 기존 59개 테스트의 처리 (2차 검토 정리): GUI 테스트 8개(`test_gui_flow.py`)는 M11에서 `src/gui/`와 함께 제거한다. repository 테스트 9개(`test_repositories.py`)는 CSV 저장소를 검사하므로 M11에서 제거한다. 나머지 42개(answer_checker, day_planner, file_utils, quiz_builder, word_service)는 웹 전환 후에도 핵심 로직 회귀 테스트로 유지한다. `file_utils`는 웹에서 쓰지 않으므로 유지 여부를 M11에서 함께 정한다.

## 9. 설계 결정 (ADR 형식)

### D-IMP01 테스트는 `unittest` + `TestClient`
- **배경**: 기존 59개 테스트가 `unittest`다. 같은 도구를 쓰면 실행 명령이 바뀌지 않는다.
- **대안**: pytest로 전환. 편리하지만 기존 명령과 테스트 구조를 모두 바꿔야 해서 제외.

### D-IMP02 core는 텍스트 키 그대로, 매핑은 웹 서비스 계층에서
- **배경**: core 로직은 검증된 상태이고, 키를 바꾸면 59개 테스트를 모두 다시 맞춰야 한다.
- **대안**: core를 `word_id` 기반으로 바꿈. 깔끔하지만 변경 범위가 크고 위험이 높다.
- **결과**: 웹 서비스가 변환을 맡는다. 같은 회원 안에서 `word_key`가 유일하므로 텍스트 키가 안전하다 (D-24).

### D-IMP03 웹 코드는 `src/web/`, 기존 패키지 import 방식 유지
- **대안**: `src/` 전체를 패키지화. 기존 import를 전부 바꿔야 해서 제외.

### D-IMP04 소셜 로그인은 직접 구현
- **배경**: 제공자가 두 곳이고 흐름이 정해져 있다.
- **대안**: 인증 전용 라이브러리 (범용이지만 설정이 많음). 필요해지면 교체 가능하게 어댑터로 분리한다.

### D-IMP05 가상환경 `.venv`와 Python 3.15 사용
- **배경**: 이 PC에 설치된 Python은 3.15.2 하나이고, 기존 문서는 3.14 기준이었다. 웹 패키지를 시스템 Python에 설치하면 다른 프로젝트와 섞인다.
- **대안**: 시스템 Python에 설치 (명령은 그대로지만 환경을 재현하기 어려움), Python 3.14 추가 설치 (3.15.2에서 설치와 테스트가 통과해 필요 없음).
- **결과**: 저장소 안 `.venv`를 쓰고 Git에서 제외한다. 테스트와 웹 실행은 `.venv`의 Python으로 한다.

### D-IMP06 웹 테스트 폴더는 `tests/web_tests/`
- **배경**: `unittest discover -s tests`는 `tests/`를 최상위로 보므로 `tests/web/`은 `web` 패키지가 되어 `src/web/`과 이름이 겹친다. 시험해 보니 `No module named 'web.app'` 오류가 났다.
- **대안**: 실행 명령에 `-t .` 추가 (이 프로젝트에서 import 오류가 나는 옵션, CLAUDE.md 특화 메모), `src/web/` 이름 변경 (D-IMP03의 구조를 바꿈).
- **결과**: 테스트 폴더 이름만 바꾼다.

### D-IMP07 환경변수는 pydantic-settings로 읽는다
- **배경**: 배포 설계 §2는 설정을 환경변수로 읽고 개발에서는 `.env`를 쓰도록 정했다. 표준 라이브러리에는 `.env`를 읽는 기능이 없다.
- **대안**: `.env` 읽는 코드를 직접 작성, `os.environ`만 사용 (개발할 때 매번 환경변수를 지정해야 함).
- **결과**: pydantic-settings를 쓴다. `APP_ENV` 기본값은 `production`으로 두어, 설정을 빠뜨려도 API 문서가 열리지 않게 한다 (D-API07).

### D-IMP08 앱은 `--factory`로 실행하고 `DATABASE_URL`은 필수
- **배경**: 운영에서 DB 주소를 빠뜨렸을 때 빈 SQLite로 조용히 뜨면 사고를 늦게 알게 된다. 필수로 만들면 모듈 전역의 `app = create_app()`은 `.env` 없는 환경에서 import만 해도 실패한다.
- **대안**: 코드에 기본 주소 내장, 주소 없이 시작한 뒤 `/healthz` 503 반환.
- **결과**: `DATABASE_URL`이 없거나 DB에 연결할 수 없으면 앱이 시작되지 않는다. 실행 명령은 `uvicorn --factory web.app:create_app --app-dir src`다. 결정 전체는 GitHub 이슈 #8에 있다.

### D-IMP09 단어 중복 검사와 검색은 SQL로 구현
- **배경**: 계획은 `word_service`의 검증·검색을 그대로 호출하기로 했지만, `validate`와 `filter_by_keyword`는 단어 전체를 메모리에 올려야 한다.
- **대안**: 요청마다 전체를 읽어 호출 (수천 개에서 느리고 동시 요청의 중복을 막지 못함).
- **결과**: 같은 규칙(소문자 키, 대소문자 무시 검색)을 SQL과 부분 유일 인덱스로 구현한다. `split_meanings`와 빈 값 검사는 core를 호출한다. API 설계 D-API03과 일치한다.
