## 1. 전제

- 결정 기록(D-W01~D-W06)과 이 문서의 결정(D-W07~D-W18)을 따른다.
- 기존 규칙을 유지한다: 단어 소프트 삭제와 학습 기록 유지 (D-09, D-12 → D-W07), 단어 이름 변경 시 연결 유지 (D-13 → D-W08), 같은 단어는 대소문자 무시 중복 (D-24), 시험마다 오답 집계 (D-11).
- 키 규칙: 대부분의 테이블은 정수 `id`를 기본 키로 쓴다. 예외는 두 가지다.
  - `settings`: `user_id`가 기본 키 (회원당 한 행)
  - `study_records`: `(user_id, word_id)`가 복합 기본 키
- 설계는 테이블·열·제약 수준까지만 쓴다. SQL은 구현 단계에서 쓴다 (CLAUDE.md 문서 규칙).
- 시각은 UTC로 저장한다 (D-W11).

## 3. 테이블 상세

### 3.1 `users` (회원)

| 열 | 타입 | 필수 | 설명 |
|----|------|------|------|
| id | 정수 | O | 기본 키 |
| email | 문자열 | O | 로그인 아이디. 저장 시 소문자로 정규화. 유일 |
| password_hash | 문자열 | X | argon2id 해시. 소셜 전용 계정은 비어 있음 |
| display_name | 문자열 | O | 화면 표시 이름 |
| email_verified_at | 일시 | X | 이메일 인증 완료 시각 |
| terms_agreed_at | 일시 | O | 이용약관 동의 시각 |
| privacy_agreed_at | 일시 | O | 개인정보 처리방침 동의 시각 |
| created_at | 일시 | O | 가입 시각 |

- **탈퇴는 행을 실제로 지운다 (하드 삭제, D-W12).** `deleted_at` 열은 두지 않는다.
- 탈퇴한 회원의 이메일은 행이 사라지므로 다시 가입할 수 있다 (확정 사항).
- 소셜로 가입해도 이메일은 필수다 (D-W13). 제공자가 이메일을 주지 않으면 §4.3 절차로 받는다.

### 3.2 `social_accounts` (소셜 연결)

| 열 | 타입 | 필수 | 설명 |
|----|------|------|------|
| id | 정수 | O | 기본 키 |
| user_id | 정수 | O | `users.id`, 회원 삭제 시 함께 삭제 |
| provider | 문자열 | O | `google` / `kakao` |
| provider_user_id | 문자열 | O | 제공자 쪽 고유 번호 |
| email_at_link | 문자열 | X | 연결 당시 제공자 이메일 (참고용) |
| created_at | 일시 | O | 연결 시각 |

- `(provider, provider_user_id)`는 유일하다. 같은 소셜 계정이 두 회원에 붙지 않는다.

### 3.3 `words` (회원별 단어장)

| 열 | 타입 | 필수 | 설명 |
|----|------|------|------|
| id | 정수 | O | 기본 키. 이름이 바뀌어도 변하지 않음 |
| user_id | 정수 | O | `users.id`, 회원 삭제 시 함께 삭제 |
| word | 문자열 | O | 표시용 단어 (앞뒤 공백 제거, 원래 대소문자 유지). 입력 100자 이하 |
| word_key | 문자열 | O | 중복 판정용 소문자 단어 |
| meaning | 문자열 | O | 한글 뜻, 여러 개면 `/` 구분. 입력 500자 이하 |
| deleted_at | 일시 | X | 단어 소프트 삭제 표시 (D-W07) |
| created_at | 일시 | O | 등록 시각 |
| updated_at | 일시 | O | 마지막 수정 시각 |

- 유일 제약: `(user_id, word_key)`는 `deleted_at`이 비어 있는 행끼리만 유일하다 (부분 유일 인덱스, D-24).

### 3.4 `settings` (회원별 설정)

| 열 | 타입 | 필수 | 설명 |
|----|------|------|------|
| user_id | 정수 | O | 기본 키이자 `users.id`. 회원 삭제 시 함께 삭제 |
| daily_new_count | 정수 | O | 기본 20, 1 이상 (D-23) |
| daily_review_count | 정수 | O | 기본 5 |
| daily_wrong_count | 정수 | O | 기본 5 |
| wrong_threshold | 정수 | O | 기본 3 |
| test_format | 문자열 | O | `multiple` / `subjective` |
| test_direction | 문자열 | O | `en_ko` / `ko_en` / `both` |
| current_day | 정수 | O | 마지막으로 만든 일차 (0이면 없음) |
| memorize_cursor_item_id | 정수 | X | **미사용 (M5).** 항상 비어 있다. 원래 마지막으로 보던 암기 카드 (`plan_items.id`)용 |

- DB CHECK는 `daily_new_count >= 1`과 형식·방향의 허용 값에 있다. 나머지 범위는 `PUT /settings`의 서비스 검사로 막는다 (API §4). 이 값들을 쓰는 경로가 하나뿐이기 때문이다. 쓰는 경로가 늘면 CHECK 추가를 다시 검토한다.
- `memorize_cursor_item_id`는 M5에서 쓰지 않기로 했다. 첫 번째 미완료 카드가 곧 이어 볼 카드이기 때문이다 (API §5). 마이그레이션 비용을 피하려고 열은 남겼다. 카드를 건너뛰는 기능이 생기면 쓰거나, 그때까지 필요 없으면 지운다.

### 3.6 `plan_items` (일차별 진도)

| 열 | 타입 | 필수 | 설명 |
|----|------|------|------|
| id | 정수 | O | 기본 키 |
| user_id | 정수 | O | `users.id` |
| day | 정수 | O | 일차 번호 (1부터) |
| word_id | 정수 | O | `words.id` |
| assigned_type | 문자열 | O | `new` / `review` / `wrong` |
| done | 불리언 | O | 암기 완료 여부, 기본 거짓 |
| position | 정수 | O | 같은 일차 안의 순서 |

| 열 | 타입 | 필수 | 설명 |

### 3.10 `auth_sessions` (로그인 세션과 가입 대기 상태)

| 열 | 타입 | 필수 | 설명 |
|----|------|------|------|
| id | 정수 | O | 기본 키 |
| user_id | 정수 | X | `users.id`. 가입 대기 상태(§4.3)에서는 비어 있음 |
| token_hash | 문자열 | O | 세션 값의 SHA-256 해시. 유일 |
| created_at | 일시 | O | 발급 시각 |
| last_seen_at | 일시 | O | 마지막 요청 시각 |
| expires_at | 일시 | O | 만료 시각 (절대 14일, 활동 없으면 3일) |
| user_agent_hash | 문자열 | X | 기기 구분용 해시. 쓰는 기능이 없어 M2에서는 채우지 않음 |
| csrf_token_hash | 문자열 | O | CSRF 토큰의 SHA-256 해시. 세션마다 하나 (API 설계 §1.2). 로그인 세션은 필수, 가입 대기 세션은 발급 후 채움 |

| 열 | 타입 | 필수 | 설명 |
|----|------|------|------|
| id | 정수 | O | 기본 키 |

## 4. 규칙

### 4.1 단어 삭제 (소프트 삭제, D-W07)
- `words.deleted_at`만 채운다. 행이 남으므로 `study_records`가 살아 있다.
- 같은 트랜잭션에서 `plan_items`의 해당 행을 지운다 (D-12).
- 같은 단어를 다시 추가하면 삭제된 행을 되살리고 새 표기와 뜻으로 바꾼다. `id`와 등록일이 유지되어 이전 기록이 이어진다. 같은 키의 삭제 행이 여럿이면 가장 최근에 지운 행을 되살린다.

### 4.2 단어 이름 변경 (D-W08)
- `words.id`가 그대로이므로 자식 테이블을 고치지 않는다. `word`와 `word_key`만 바꾼다.
- 바꾼 이름이 살아 있는 다른 단어와 겹치면 중복으로 거절한다 (D-24).

### 4.3 소셜 가입과 이메일 (D-W13)
1. 제공자 인증이 끝나면 `social_accounts`에 있는지 먼저 확인한다. 있으면 그 회원으로 로그인한다.
2. 없으면 `auth_sessions`에 **가입 대기 세션**(`user_id` 없음, `pending_*` 채움)을 만든다.
3. 제공자가 이메일을 주고 이메일 인증됨을 알려주면, 같은 이메일의 회원이 있을 때만 연결을 시도한다 (인증 설계 §4.2 규칙 2).
4. 제공자가 이메일을 주지 않으면 **이메일 입력 단계**로 보낸다. 입력한 이메일로 인증 메일을 보내고, 인증이 끝나야 `users` 행을 만든다.
5. 이 과정에서 같은 이메일의 기존 회원이 있으면 중복 응답 규칙(인증 설계 D-A04)을 따른다. 기존 회원에게 "이미 가입된 이메일입니다" 메일을 보내고, 화면에는 같은 응답을 준다.
6. 가입 대기 세션은 24시간 후 만료한다.

### 4.4 탈퇴 (하드 삭제, D-W12)
`users` 행 하나를 지운다. 나머지는 외래 키 CASCADE로 DB가 같은 문장 안에서 함께 지운다 (D-W14). 서비스 코드에서 테이블별로 차례대로 지우지 않는다.
- 함께 지워지는 테이블: `social_accounts`, `words`, `settings`, `study_records`, `plan_items`, `test_sessions`, `test_attempts`, `test_attempt_items`, `auth_sessions`, `auth_tokens`
- `login_attempts`는 회원과 연결되지 않으므로 보관 기간에 따라 자연 삭제된다 (해시만 있음).
- 백업에 남은 데이터는 배포 설계 §5의 보관 기간 후 소멸한다.

## 6. 설계 결정

### D-W07 단어 삭제는 소프트 삭제 (v0.7 승격)
- **배경**: 기존 결정 D-09, D-12는 "단어를 지워도 학습 기록은 남긴다"이다. 단어 행을 실제로 지우면 기록을 그 행에 연결해 둘 수 없다.
- **대안**: (a) 하드 삭제 후 기록을 단어 문자열로 따로 보관, (b) 소프트 삭제 (채택).
- **결정 근거**: (b)는 `word_id`로 연결을 유지해 이름 변경(D-13)도 그대로 처리된다. 한 행만 살려 두면 되므로 규칙이 단순하다.
- **비용**: 유일 제약에 부분 인덱스가 필요하다. PostgreSQL에서도 지원된다.

### D-W08 기록과 진도의 연결 키는 `word_id` (v0.7 승격)
- **배경**: 기존 CSV는 단어 문자열을 키로 썼다. 이름 변경 때 여러 파일을 고쳐야 했다.
- **대안**: 기존처럼 단어 문자열을 키로 유지.
- **결정 근거**: 모든 자식 테이블을 `word_id`로 연결하면 이름 변경 때 자식 테이블을 건드리지 않는다 (§4.2).

### D-W09 설정은 회원당 한 행 (v0.7 승격)
- **배경**: 기존 설정 파일은 key/value 여러 줄이다.
- **대안**: key/value 테이블 유지 (항목을 추가해도 스키마가 바뀌지 않지만 값 검증이 약함).
- **결정 근거**: 열로 펼치면 타입과 검사 제약을 DB에서 걸 수 있다. 설정 항목이 고정돼 있어 펼쳐도 불편이 없다.

### D-W10 `current_day`는 저장값으로 유지 (v0.7 승격, 잠정)
- **배경**: 기존 설정에 있는 값이고, 최대 일차 `MAX(day)`로 계산할 수도 있다.
- **대안**: `plan_items`에서 계산 (저장값 없음).
- **결정 근거**: 기존 동작을 그대로 옮기고, 일차 생성의 조건부 갱신(API §5)에 이 값을 쓴다. 클라이언트는 이 값을 바꿀 수 없다.
- **확인**: 진도가 없을 때 0이어야 한다. 기본값 0은 M1 테스트에, 진도와 값의 일치는 M5 테스트(`test_current_day_matches_created_days`)에 있다. 불일치가 생기면 계산 방식으로 바꾼다.

### D-W11 시각은 UTC로 저장하고 한국 시간으로 표시 (v0.7 승격)
- **배경**: 서버 위치와 무관하게 시각이 맞아야 한다.
- **대안**: 한국 시간으로 저장.
- **결정 근거**: UTC로 저장하면 서버 위치의 영향을 받지 않는다. 한국 서비스이므로 표시는 한국 시간으로 고정한다. 앱에서 강제하는 방법은 D-W17에 있다.
- **v0.1과 달라진 점**: 기존 `taken_at` 문자열의 변환 규칙을 뺐다. 기존 데이터를 옮기지 않기 때문이다 (작업계획 §11).

### D-W12 탈퇴는 하드 삭제
- **배경**: v0.1은 `users.deleted_at`으로 소프트 삭제하고 `email` 유일 제약을 그대로 두었다. 이 조합은 탈퇴 후 재가입 허용과 충돌했다. 인증·배포 문서는 즉시 삭제를 전제로 썼다.
- **대안**: (a) 소프트 삭제 + 부분 유일 인덱스 (`deleted_at IS NULL`), (b) 하드 삭제 (채택).
- **결정 근거**: 탈퇴한 사람의 데이터는 서비스에서 즉시 사라져야 한다는 것이 처리방침과 확정 사항이다. 소프트 삭제는 개인정보를 남긴 채 보관하게 된다. 하드 삭제가 규칙도 단순하다.
- **영향**: `users`에 `deleted_at`을 두지 않는다. `email`은 단순 유일 제약이다.

### D-W13 가입 이메일은 필수
- **배경**: 카카오는 이메일을 선택 동의로 받는다. 이메일이 없는 회원은 비밀번호 재설정과 수동 연결을 할 수 없어 계정이 막힌다.
- **대안**: (a) 이메일 없는 소셜 회원 허용 (재설정 경로가 없어져 제외), (b) 가입 시 이메일을 항상 받음 (채택).
- **결정 근거**: 모든 회원이 이메일을 가진다. 소셜로 가입해도 이메일 입력 단계에서 받는다 (§4.3).
- **영향**: `users.email`은 NOT NULL이다. 소셜 가입은 가입 대기 세션을 거친다.
- **확인 필요**: 카카오가 이메일 인증 여부를 알려주는 조건은 공식 문서로 확인해야 한다. 확인 전까지는 §4.3 규칙 4를 기본 경로로 본다.

### D-W14 외래 키 삭제 방식 (v0.3 추가)
- **배경**: v0.2 §4.4는 테이블별 삭제 순서를 적었지만, `test_sessions`가 참조하는 `test_attempts`를 먼저 지우는 순서여서 외래 키 오류가 났다 (M1 구현 중 발견). 다른 외래 키의 삭제 동작도 정해지지 않았다.
- **대안**: (a) 삭제 순서만 바로잡고 서비스 코드에서 차례대로 지움, (b) 모든 외래 키에 CASCADE, (c) 회원 소유 관계만 CASCADE (채택).
- **결정 근거**: 회원 행 삭제 한 번으로 끝나 테이블이 늘어도 빠뜨릴 일이 없다. `word_id`에는 CASCADE를 두지 않아, 단어 행을 실수로 지우면 학습 기록을 잃지 않고 오류가 난다 (D-W07).
- **영향**: `user_id`, `test_attempt_items.attempt_id`는 CASCADE. `settings.memorize_cursor_item_id`는 SET NULL. `word_id`, `test_sessions.attempt_id`는 기본 동작이며, 미제출 세트 폐기는 `test_sessions`가 참조하지 않는 세트만 대상으로 한다. SQLite 테스트로 확인했고, PostgreSQL 실행 확인은 M10 전에 한다.

### D-W15 값과 관계를 DB 제약으로도 막음 (v0.6, M1 결정)
- **배경**: 설계에 명시된 제약만으로는 잘못된 값과 느린 조회를 막기 어렵다.
- **대안**: 서비스 코드에서만 검사 (동시 요청과 코드 실수를 막지 못함).
- **결정 근거**: 값이 정해진 문자열 열에 CHECK를 둔다. `test_sessions.attempt_id`는 유일로 해 두 번 제출을 DB에서도 막는다. `auth_sessions`는 로그인 세션과 가입 대기 세션 중 하나만 되도록 CHECK를 둔다. PostgreSQL은 외래 키 인덱스를 자동으로 만들지 않으므로 외래 키와 정리 작업용 열에 인덱스를 둔다.

### D-W16 문자열 길이는 형식이 정해진 값에만 (v0.6, M1 결정)
- **결정 근거**: 해시 64자, 이메일 254자(RFC 5321), 표시 이름 100자, 제공자 고유 번호 255자, 코드값에 길이를 둔다. 단어와 뜻, 문제와 정답은 `Text`로 두고 길이는 입력 검사에서 제한한다 (단어 100자, 뜻 500자). 규칙이 바뀌어도 마이그레이션이 필요 없다.

### D-W17 시각은 앱에서 UTC로 강제 (v0.6, M1 결정)
- **배경**: SQLite는 시간대 정보를 저장하지 않아 D-W11을 DB에 맡길 수 없다.
- **대안**: 기본 `DateTime` (DB마다 동작이 달라짐).
- **결정 근거**: 모든 일시 열에 `UtcDateTime` 타입을 쓴다. 시간대 없는 값은 잘못 저장하기 전에 오류를 낸다.

### D-W18 SQLite와 PostgreSQL의 동작 차이를 줄임 (v0.6, M1 결정)
- **결정 근거**: SQLite 연결마다 `PRAGMA foreign_keys=ON`을 켠다 (기본값은 꺼짐이라 개발에서 놓친 오류가 운영에서 터진다). 부분 유일 인덱스에 `sqlite_where`와 `postgresql_where`를 함께 지정한다. 제약 이름은 `naming_convention`으로 정해 이후 마이그레이션에서 지목할 수 있게 한다.
- **한계**: 실제 PostgreSQL 실행은 아직 하지 않았다 (테스트 정의서 §5).
