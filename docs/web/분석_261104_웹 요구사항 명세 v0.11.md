## 1. 이 문서의 위치

- 설계 문서가 "어떻게"를 정한다면, 이 문서는 "무엇을"을 정한다 (개발방법론 §2.2). 새 요구사항을 만들지 않고, 흩어진 확정 사항을 한곳에 모은다.
- **근거 문서**: 기획서(데스크톱 기능 F-01~F-12), 결정 기록, 데이터 모델, 인증·보안, API, 화면, 배포·운영, 구현 계획, 테스트 정의서 (모두 `docs/web/`의 최신 버전과 `docs/` 기획서).
- 내용이 충돌하면 결정 기록과 설계 문서가 우선한다. 이 문서는 추적을 위한 목록이다.

### 1.1 표기

**상태**

| 표기 | 뜻 |
|------|-----|
| 완료 | 구현했고, 근거 테스트가 통과한다 |
| 부분 | 일부만 구현했거나 일부 환경에서 확인하지 못했다. 남은 내용을 함께 적는다 |
| 예정 | 아직 구현하지 않았다. 마일스톤을 함께 적는다 |
| 폐기 | 요구가 바뀌어 없앴다. 코드와 API도 지웠고 ID는 다시 쓰지 않는다 |

|------|-----|

| 공개 | 시연에는 없어도 되지만, 정식 공개 서비스(D-W04)를 열기 전에는 꼭 필요하다 |

## 2. 사용자와 범위

- **회원**: 영어 단어를 외우려는 개인 학습자. 담은 단어, 설정, 진도, 기록을 가진다 (D-W06). 단어는 직접 쓰지 않고 공용 단어장에서 담는다 (D-WB01).
- **미인증 회원**: 가입했지만 이메일 인증 전인 회원. 읽기만 할 수 있다.
- **비회원**: 가입과 로그인만 할 수 있다.
- **운영자**: 배포와 백업을 맡고, 명령줄 도구로 공용 단어장을 등록한다. 관리자 화면은 범위 밖이다.

**범위 밖 (기획서 §3.7 유지)**: 발음 재생, 외부 사전 연동, 학습 통계 그래프, 관리자 화면, 네이버 로그인, 기존 CSV 데이터 이관(작업계획 §11).
