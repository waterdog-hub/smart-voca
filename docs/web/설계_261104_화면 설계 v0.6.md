# smart-voca 웹 서비스 — 화면 설계

**파일 위치**: `docs/web/설계_261104_화면 설계 v0.6.md`
**작성일**: 2026-11-04
**버전**: v0.6 (M4 설정 화면 구현 반영)
**설명**: 공개·회원 화면의 목록, 화면 구성, 사용자 흐름, 상태별 표시(빈 상태·오류·인증 전)를 정리한 5단계 설계 문서

---

## 1. 전제

- 결정 기록, 데이터 모델, 인증·보안 설계, API 설계의 최신 확정 사항을 따른다.
- 기존 데스크톱 화면(`src/gui/`: 단어장, 암기, 시험, 설정 탭과 대화상자 3개)의 기능을 웹 화면으로 옮긴다.
- 화면 배치의 실제 모습(색, 여백)은 이 문서 범위에서 제외한다. 필요하면 다음 단계에서 목업으로 만든다 (§9).

## 2. 탭 구조 → 페이지 구조

| 기존 (데스크톱) | 웹 | 이유 |
|-----------------|-----|------|
| 탭 4개 (단어장, 암기, 시험, 설정) | 좌측 메뉴 + 페이지 (홈, 단어장, 암기, 시험, 시험 기록, 설정, 내 계정) | 웹은 주소(URL)로 화면을 구분해야 새로고침·뒤로가기·공유가 된다 |
| 대화상자 (단어 수정, 일차 보기, 시험 기록) | 페이지 또는 같은 페이지 안의 패널 | 대화상자는 뒤로가기로 닫을 수 없다. 단어 수정처럼 짧은 작업만 패널로 둔다 |

**결정 (D-UI01)**: 페이지 구조를 쓴다. 기존 탭의 묶음은 메뉴 항목으로 그대로 옮긴다. 기존 4개 탭 기능은 모두 남는다. 추가되는 것은 홈, 시험 기록, 내 계정이다.

## 3. 화면 목록

### 3.1 공개 화면 (로그인 전)

| ID | 화면 | 주요 요소 | 연결 API |
|----|------|-----------|----------|
| P-01 | 시작 (소개) | 서비스 소개, 로그인·가입 버튼 | 없음 |
| P-02 | 로그인 | 이메일, 비밀번호, 로그인 버튼, 구글·카카오 버튼, 가입·재설정 링크 | `POST /auth/login`, `GET /auth/social/{p}/start` |
| P-03 | 가입 | 이메일, 비밀번호, 표시 이름, 이용약관·개인정보 처리방침 동의 체크 (필수) | `POST /auth/signup` |
| P-04 | 인증 메일 안내 | "메일을 보냈습니다", 로그인 화면 링크. 재발송은 로그인 후 인증 안내 띠에서 한다 (D-UI07) | 없음 |
| P-05 | 인증 결과 | 성공 또는 실패 (만료·사용됨) 문구, 로그인 화면 이동. 같은 탭에 새 링크를 붙여 넣어도 다시 확인한다 | `POST /auth/verify-email` |
| P-06 | 재설정 요청 | 이메일 입력, "메일을 보냈을 수 있습니다" 문구 (가입 여부 노출 없음) | `POST /auth/password-reset/request` |
| P-07 | 새 비밀번호 설정 | 새 비밀번호, 확인 입력 | `POST /auth/password-reset/confirm` |
| P-08 | 계정 연결 확인 | 같은 이메일의 기존 계정이 있음, 비밀번호 입력 후 연결 (인증 설계 §4.2 규칙 4) | `POST /auth/social/{p}/link` |

## 4. 화면 구성 (와이어프레임)

### 4.1 회원 공통 틀
```
+------------+-------------------------------------------------+
| 홈         | (인증 전이면 안내 띠)                           |
| 단어장     | 페이지 제목                                     |
| 암기       | 알림 영역                                       |
| 시험       |                                                 |
| 시험 기록  |                 (선택한 페이지)                  |
| 설정       |                                                 |
| 내 계정    |                                                 |
|            |                                                 |
| 이름 님    |                                                 |
| [로그아웃] |                                                 |
+------------+-------------------------------------------------+
```
- 상단 바는 두지 않는다. 회원 이름과 로그아웃은 메뉴 아래쪽에 있다. 진행률은 홈(H-01)에서 보여 준다 (FR-PLAN-06). "내 계정"은 A-01을 구현하는 M7에 메뉴로 추가한다.
- 인증 전이면 본문 위에 띠 배너: "이메일 인증이 필요합니다", [인증 메일 다시 받기]. 쓰기 버튼은 비활성처럼 보이게 하고(`aria-disabled`), 눌렀을 때 같은 안내를 띄운다.
- 좁은 화면에서는 좌측 메뉴를 접고 상단 메뉴로 바꾼다 (반응형).
- 메뉴에는 구현한 화면만 표시한다. 누르면 404가 나는 항목을 두지 않는다.
- 넓은 화면의 메뉴는 화면 높이에 고정한다. 긴 목록에서도 로그아웃 버튼이 보여야 한다.
- 알림 영역은 제목 바로 아래에 둔다. 긴 화면에서 알림이 화면 밖으로 나가지 않게 한다.

### 4.2 암기 (M-01)
```
일차: [3일차 ▼]   진행 12/20 ███████░░░░
+--------------------------------------------------+
|                    apple                         |
|                                                  |
|           [ 뜻 보기  (↑ / Space) ]               |
|                                                  |
|   사과                                           |
+--------------------------------------------------+
|     [ 다시 (← / 2) ]      [ 외움 (→ / 1) ]       |
+--------------------------------------------------+
```
- 뜻은 펼치기 전에는 가린다. 펼친 뒤 "외움" 또는 "다시"를 누른다.
- 키보드: 뜻 보기는 ↑ 또는 Space, 외움은 → 또는 1, 다시는 ← 또는 2다 (F-12, D-17, D-UI09). 단축키 안내를 화면 하단에 작게 표시한다.
- 20개를 모두 처리하면 요약 카드: 외운 수, 다시 한 수, 다음 일차 만들기 버튼 (H-01로 이동 가능).

### 4.3 단어장 (W-01)
```
[ 검색: ________ ]  [가져오기] [내보내기]      총 1,988개
+-------------------------------------------------------+
| [ ] 단어 ▲      | 뜻              | 등록일            |
+-------------------------------------------------------+
| [ ] apple       | 사과            | 2026-10-21        |
| [ ] run         | 달리다/운영하다 | 2026-10-21        |
+-------------------------------------------------------+
[ 단어 ____ 뜻 ____ ] [추가]              [선택 삭제]
```
- 정렬은 열 제목을 누른다. 검색은 입력 후 짧게 기다렸다가 서버에 요청한다.
- 삭제는 선택 개수를 적은 확인 창을 거친다 (기존 동작 유지).
- 목록은 페이지 단위로 넘긴다 (API §1.4). 한 번에 50행.
- 단어장이 비었으면 빈 상태 안내: "단어를 추가하거나 CSV 파일을 가져오세요." CSV 형식은 화면 아래 접힌 안내로 항상 볼 수 있다.
- 좁은 화면에서는 표의 행을 카드로 바꾼다 (D-UI06).

### 4.4 시험 (T-01~T-03)
```
시험 준비
  형식: 객관식      방향: 영→한      문항 수: 20
  [ 시험 시작 ]
```
```
시험 3/20  ███░░░░
apple 의 뜻은?
  1) 사과   2) 달리다   3) 나무   4) 바다      (숫자키 1~4)
                         [ 다음 ]
```
- 제출 전에 확인 창: "아직 답하지 않은 문항이 2개 있습니다. 제출할까요?"
- 결과 화면에서 틀린 문항만 보기 버튼을 둔다.

### 4.5 설정 (S-01)
- 숫자 입력칸마다 최소값을 칸 아래에 적는다. 예: "1 이상".
- 값이 잘못되면 저장 버튼을 누르기 전에 칸 아래에 바로 안내한다 (서버 검증과 같은 규칙). 안내 문구는 "1 이상 9999 이하로 입력해 주세요."다.
- 칸 목록과 범위는 서버(`setting_service.COUNT_FIELDS`)가 템플릿에 넘기고, 자바스크립트는 입력칸의 `min`, `max`를 읽는다. 규칙을 두 곳에 적지 않는다.
- 저장과 되돌리기는 값을 불러온 뒤에 켠다. 빈 칸을 저장하는 일을 막는다.
- 되돌리기는 마지막으로 저장한 값으로 복원하고 칸 안내와 알림을 지운다.
- 저장하면 "설정을 저장했습니다. 하루 분량은 다음 일차 진도부터 적용됩니다."를 띄운다. 이미 만든 일차는 바뀌지 않는다고 화면에 적는다.
- 인증 전에도 값을 볼 수 있다. 저장은 §4.1의 규칙대로 안내만 띄운다.
- 저장은 자바스크립트로 JSON API를 호출한다. 서버 폼을 따로 두면 같은 검사 경로가 둘이 되기 때문이다 (D-UI08과 같은 이유).

### 4.6 내 계정 (A-01)
- 탈퇴는 가장 아래에 두고, 버튼을 누르면 "단어장·진도·기록이 모두 삭제되며 되돌릴 수 없습니다" 확인과 비밀번호 입력을 요구한다.
- 소셜 계정 연결 상태를 "연결됨 / 연결 안 됨"으로 표시하고, 마지막 로그인 수단은 해제 버튼을 비활성화한다 (API §2 `LAST_LOGIN_METHOD`).

## 5. 사용자 흐름

### 5.1 처음 쓰는 사람
```
P-01 → P-03 가입 → P-04 인증 메일 안내 → (메일 링크) → P-05 인증 완료
  → H-01 홈 (빈 상태: "단어장부터 만드세요")
  → W-01 단어장 (가져오기 또는 추가) → S-01 설정 확인
  → H-01 "다음 일차 만들기" → M-01 암기 → T-01 시험 → T-03 결과
```

### 5.2 돌아온 사람
- 로그인 → H-01: 현재 일차 완료율과 "이어서 암기하기" 버튼. 마지막 카드 위치에서 이어간다 (D-10).

### 5.3 세션 만료
- 요청이 `401`을 받으면 로그인 화면(P-02)으로 보내고, 로그인 후 원래 페이지로 돌아가게 한다.
- 시험을 보는 중이었다면 시험 문제는 서버에 남아 있으므로 `GET /tests/{id}`로 복원한다 (API §6).

### 5.4 소셜 로그인
- 구글·카카오 버튼 → 제공자 화면 → 콜백. 같은 이메일 계정이 있고 자동 연결이 안 되면 P-08로 이동.

## 6. 상태별 표시

| 상태 | 표시 방식 |
|------|-----------|
| 로딩 | 새 결과가 올 때까지 이전 목록을 그대로 두고 `aria-busy`로 알린다. 스켈레톤은 쓰지 않는다. 저장 버튼은 요청 중 비활성 (중복 클릭 방지, D-API05). 단어 삭제 버튼은 아직 비활성 처리가 없다 (M5에서 처리) |
| 빈 상태 | 단어장, 진도, 시험 기록에 각각 다음 할 일 안내 문구 |
| 입력 오류 | 해당 칸 아래 `!` 표시와 한글 안내 (색만으로 구분하지 않음). 칸 테두리 색도 바꾼다. 단어장 폼은 아직 테두리 색과 `aria-invalid`가 없다 (M5에서 처리) |
| 서버 오류 | 제목 바로 아래 알림 영역 (`role="alert"`, 사라지는 토스트를 쓰지 않음). 화면 입력값은 지우지 않는다 |
| 인증 필요 | 띠 배너 + 쓰기 버튼 비활성 + 누르면 안내 |
| 충돌 (`409`) | 예: "이미 있는 단어입니다" 또는 "다음 일차를 만들 수 없습니다. 오늘 진도를 먼저 끝내세요" |
| 시험 불가 (`422`) | 시험 시작 버튼 비활성, 이유 표시 (단어 수 부족 등) |

## 7. 접근성 기준

- 모든 입력칸에 라벨을 둔다. 자리표시자 글자만으로 이름을 대신하지 않는다.
- 키보드만으로 모든 기능을 쓸 수 있어야 한다 (Tab 순서, 포커스 표시).
- 결과와 오류는 화면 낭독기가 읽을 수 있게 알림 영역에 표시한다.
- 글자와 배경의 대비는 WCAG AA (4.5:1) 이상.

## 8. 설계 결정 (ADR 형식)

### D-UI01 페이지 구조 (탭 대신)
- **배경**: 웹은 URL로 화면을 구분해야 한다 (§2).
- **대안**: 한 화면에 탭 유지. 새로고침하면 탭 상태가 사라져 제외.

### D-UI02 암기·시험 화면의 키보드 단축키 유지
- **근거**: 기존 데스크톱 기능 (F-12, D-17). 같은 단축키로 익숙한 흐름을 유지한다.
- **주의**: 입력칸에 커서가 있을 때는 단축키가 동작하지 않게 한다 (글자 입력과 충돌 방지).

### D-UI03 제출 전 확인과 삭제 확인
- **근거**: 시험 제출과 단어 삭제는 되돌리기 어렵다 (기존 동작 유지).

### D-UI04 단어 수정은 패널로
- **근거**: 목록 맥락을 잃지 않고 빨리 고칠 수 있다. 대화상자보다 뒤로가기 흐름과 충돌이 적다.

### D-UI07 인증 메일 재발송은 로그인 후 (v0.2)
- **배경**: P-04는 가입 직후 화면인데, 가입은 자동 로그인이 없고 (D-A04) 재발송 API는 로그인이 필요하다. 두 규칙이 충돌했다.
- **대안**: 이메일을 받는 공개 재발송 API (요청 횟수 제한과 응답 통일을 또 만들어야 함).
- **결과**: P-04에는 로그인 안내를 두고, 재발송 버튼은 §4.1의 인증 안내 띠에 둔다.

### D-UI08 인증 폼도 자바스크립트로 JSON API를 호출 (v0.4)
- **배경**: D-UI05는 암기·시험·단어장 외에는 서버가 HTML을 그리도록 정했다. 인증 폼을 서버 폼으로 처리하면 같은 인증 규칙의 경로가 둘이 된다.
- **대안**: 서버 폼 처리를 따로 구현.
- **결과**: 폼은 작은 자바스크립트로 API를 호출해 인증 처리 경로를 하나로 둔다. 인라인 스크립트를 쓰지 않아 CSP `script-src 'self'`와 충돌하지 않는다. 자바스크립트가 꺼진 환경은 지원하지 않는다.

### D-UI09 암기 단축키는 방향키와 Space, 1, 2를 함께 지원 (v0.5, 사용자 확정)
- **배경**: §4.2의 그림은 Space, 1, 2였고 본문과 기획서 F-12는 방향키였다. M5 전에 정해야 했다.
- **대안**: 방향키만 (기존 앱과 같음), Space, 1, 2만 (기획서 변경 필요).
- **결과**: 둘 다 지원한다. 같은 동작을 두 키가 호출하므로 규칙은 하나다. 뜻을 펼치기 전에는 외움과 다시 키가 동작하지 않는다.
- **구현 주의**: Space와 방향키는 브라우저 기본 동작(스크롤, 포커스된 버튼 누르기)을 막아 한 번 눌러 두 번 처리되지 않게 한다. D-UI02의 입력칸 예외를 그대로 적용한다.

## 9. 확정 사항과 남은 질문

**확정 (사용자 답변, 2026-11-04)**
1. **프런트엔드**: 서버 템플릿 (Jinja2) + 필요한 부분만 자바스크립트 (D-UI05).
2. **반응형**: 휴대폰 화면도 전체 기능을 지원한다 (D-UI06).

**남은 질문**
1. **목업 제작**: 주요 화면(홈, 암기, 단어장)을 시각 목업으로 만들지 여부. 만든다면 다음 단계에서 진행.

### D-UI05 서버 템플릿 + 부분 자바스크립트
- **배경**: 사용자가 Python 학습을 목표로 하고 있고, 화면 상호작용은 암기·시험·단어장 정도로 한정된다.
- **대안**: React 등 별도 프레임워크. 빌드 도구와 두 언어를 함께 익혀야 해서 제외.
- **결과**: 암기·시험의 키보드 동작과 단어장 정렬·검색만 자바스크립트로 작성한다. 나머지는 서버가 HTML을 그린다.

### D-UI06 휴대폰 전체 기능 지원
- **배경**: 사용자 요청. 암기와 시험을 이동 중에 하는 사용 패턴이 있을 수 있다.
- **결과**: 모든 화면을 좁은 화면에서도 쓸 수 있게 설계한다. 단어장 표는 카드 목록으로 바꾸고, 암기 카드는 세로로 쌓는다. 화면 테스트 범위가 커지므로 구현 계획에 반영한다.
