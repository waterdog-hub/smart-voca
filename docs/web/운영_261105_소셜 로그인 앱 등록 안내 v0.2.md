# 소셜 로그인 앱 등록 안내

**파일 위치**: `docs/web/운영_261105_소셜 로그인 앱 등록 안내 v0.2.md`
**작성일**: 2026-11-05
**버전**: v0.2 (docs로 승격. 콘솔 메뉴 이름은 공식 문서로 확인하지 못해 v1.0이 아니다)
**설명**: M8 소셜 로그인을 실제 구글·카카오로 확인하려면 사용자가 해야 하는 앱 등록과 `.env` 설정 절차 (이슈 #19)

---

## 1. 먼저 알아 둘 점

- 코드는 가짜 제공자와 모의 전송으로만 확인했다. 아래 절차를 마치기 전에는 실제 로그인이 되는지 모른다.
- 제공자 콘솔 화면은 자주 바뀐다. 메뉴 이름이 다르면 같은 뜻의 항목을 찾는다. 이 문서의 메뉴 이름은 작성 시점의 기억에 기반하며 **공식 문서로 확인하지 못했다**.
- **키 값(클라이언트 비밀 등)은 `.env`에만 적는다.** 채팅, 이슈, 커밋, 스크린샷에 붙여 넣지 않는다 (`.env`는 Git에서 제외된다).
- 시연(`APP_ENV=demo`)에서는 소셜 로그인이 꺼진다. ngrok 무료 주소가 실행할 때마다 바뀌어 콜백 주소를 등록할 수 없기 때문이다. 아래는 **개발 PC(로컬)에서 확인하는 절차**다.

## 2. 콜백 주소 (두 제공자 공통)

로컬 확인용 `PUBLIC_BASE_URL`은 기본값 `http://127.0.0.1:8000`이다. 제공자 콘솔의 "승인된 리디렉션 URI"(Redirect URI)에 아래를 **글자 하나까지 같게** 등록한다.

```
http://127.0.0.1:8000/api/v1/auth/social/google/callback
http://127.0.0.1:8000/api/v1/auth/social/kakao/callback
```

- 구글은 로컬 개발용으로 `http://127.0.0.1`/`localhost` 주소를 허용하는 것으로 알고 있다. `localhost`와 `127.0.0.1`은 서로 다른 주소이므로 브라우저에서도 `127.0.0.1:8000`으로 접속한다.
- 카카오의 로컬 주소 허용 여부는 확인하지 못했다. 막히면 알려 달라.

## 3. 구글 (Google Cloud Console)

1. 프로젝트를 만든다 (이름 예: `smart-voca`).
2. "API 및 서비스" → "OAuth 동의 화면"을 설정한다. 사용자 유형은 "외부", 앱 이름과 지원 이메일을 넣고, 범위는 기본(`openid`, `email`, `profile`)이면 된다. 게시 상태가 "테스트"이면 **테스트 사용자**에 본인 계정을 추가해야 로그인된다.
3. "사용자 인증 정보" → "OAuth 클라이언트 ID 만들기" → 유형 "웹 애플리케이션". "승인된 리디렉션 URI"에 위 구글 콜백 주소를 넣는다.
4. 발급된 **클라이언트 ID**와 **클라이언트 보안 비밀번호**를 `.env`에 적는다.

```
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...
```

## 4. 카카오 (Kakao Developers)

1. "내 애플리케이션"에서 앱을 만든다.
2. "앱 키"에서 **REST API 키**를 확인한다.
3. "카카오 로그인"을 활성화(ON)하고 "Redirect URI"에 위 카카오 콜백 주소를 넣는다.
4. "동의항목"에서 **닉네임**과 **카카오계정(이메일)**을 설정한다. 이메일 동의항목은 선택 동의로 둘 수 있고, 이메일을 받지 못하면 이 서비스는 이메일 입력 단계로 보낸다. 이메일 항목을 쓰려면 앱 설정(예: 비즈 앱 전환)이 필요할 수 있다 (**확인하지 못함**).
5. "보안"에서 **Client Secret**을 쓰는 설정이면 값을 발급받는다 (선택).
6. `.env`에 적는다.

```
KAKAO_REST_API_KEY=...
KAKAO_CLIENT_SECRET=...
```

- 카카오가 이메일 인증 여부를 알려 주는 조건은 공식 문서로 확인하지 못했다. 이 서비스는 `is_email_valid`와 `is_email_verified`가 모두 참일 때만 인증된 이메일로 본다. 그렇지 않으면 이메일 입력 단계로 보내므로, 카카오 계정은 대부분 "이메일 입력 → 확인 메일" 경로로 가입될 수 있다.
- 카카오가 PKCE(`code_challenge`)를 받는지는 확인하지 못했다. 로그인이 `invalid_request` 계열로 거절되면 알려 달라.

## 5. 확인 방법

1. `.env`에 키를 적고 서버를 다시 띄운다 (`.venv\Scripts\python -m uvicorn --factory web.app:create_app --app-dir src --reload`).
2. `http://127.0.0.1:8000/login`에 키를 적은 제공자의 버튼만 나오는지 본다. 하나도 없으면 키가 읽히지 않은 것이다.
3. 버튼을 눌러 로그인하고 동의한다. 돌아오면 홈이 열려야 한다. 실패하면 로그인 화면에 실패 이유가 나온다 (`?social_error=`).
4. 서버 콘솔의 `소셜 로그인: 회원 N`, `소셜 연결 실패` 같은 줄을 본다. 제공자 응답 본문은 남기지 않는다.
5. 내 계정에서 연결·해제를 해 본다. 비밀번호 없이 소셜로 가입한 계정이 마지막 연결을 해제하려 하면 막혀야 한다.

## 6. 정식 공개 때 (M10)

- `PUBLIC_BASE_URL`이 실제 https 도메인이 되면 콜백 주소도 그 도메인으로 다시 등록한다.
- 구글은 "게시 상태"를 "프로덕션"으로 올려야 테스트 사용자 밖의 사람이 로그인한다 (검증 절차가 있을 수 있다).
- 이용약관·개인정보 처리방침 페이지가 필요하다. 지금은 소셜 로그인 버튼 아래의 문구("처음 로그인하면 동의한 것으로 봅니다")로 동의를 갈음한다 (이슈 #19). 정식 공개 전에 동의 화면을 따로 두는 것이 안전하다.
