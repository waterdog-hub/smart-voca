> 2026-11-05 리허설과 시연 전 점검에서 실제 터널로 확인했다 (§6). Ctrl+C 종료도 확인했다 (§6 시연 전 점검). 시연 직전에는 한 번 더 직접 확인한다.

## 1. 준비물

- ngrok 계정과 설치 (2026-11-04 완료. 버전 3.39). 인증 토큰은 2026-11-05 리허설에서 동작을 확인했다.
- 프로젝트 `.venv`. 처음이면 `README.md`의 웹 서비스 1단계를 따른다.
- 8000번 포트가 비어 있어야 한다. 개발 서버가 떠 있으면 먼저 끈다.
- 브라우저 점검을 쓰려면 Chrome 또는 Edge.

## 2. 실행

프로젝트 루트에서 실행한다.

```
.venv\Scripts\python ai-agent/scripts/demo_server.py start
```

1. 터널을 열고, 받은 https 주소로 설정을 만들고, DB를 준비하고(마이그레이션 후 공용 단어장 `data/wordbooks.json`을 넣는다), 서버를 띄운다.
2. 화면에 나온 **시연 주소**를 참가자에게 알려 준다.
3. Ctrl+C를 누르면 서버와 터널이 함께 닫히도록 구현했다. 닫힌 뒤 주소가 열리지 않는지 확인한다 (§8).

- `APP_ENV=demo`로 실행된다. `.env`를 고치지 않는다. 비밀 키는 실행할 때마다 새로 만들어 파일에 남기지 않는다.
- DB는 `data/smart_voca_demo.db`다. 개발 DB와 섞이지 않는다.
- 다시 실행해도 시연 DB는 남는다. 비밀 키가 바뀌므로 로그인은 다시 해야 할 수 있다.

## 3. 참가자 안내

- 주소를 열면 ngrok 경고 페이지가 나온다. **Visit**을 누른다 (무료 플랜 조건, D-W19).
- 메일 인증은 없다. 가입하면 바로 로그인할 수 있다.
- **실제 비밀번호와 개인정보를 쓰지 않는다.** 화면 위에도 같은 안내가 나온다. 이메일은 형식만 맞으면 되며, 실제 주소일 필요가 없다.
- 같은 이메일로 다시 가입하면 1분 제한이 걸릴 수 있다.
- **소셜 로그인은 쓸 수 없다.** 시연 환경에서는 켜지지 않아 로그인·가입 화면에 구글·카카오 버튼이 없다. ngrok 무료 주소가 실행할 때마다 바뀌어 제공자에 콜백 주소를 등록할 수 없기 때문이다 (이슈 #19).
- **비밀번호 재설정은 쓸 수 없다.** 시연 환경은 메일을 보내지 않아 "비밀번호를 잊었다면 다른 이메일로 새로 가입"하라는 안내가 나온다. 로그인한 상태의 비밀번호 변경, 모든 기기 로그아웃, 탈퇴(내 계정 메뉴)는 쓸 수 있다.

## 4. 시연 순서 (제안)

가입 → 단어장 담기 ("기본 영단어 1" 등 운영자가 준비한 단어장) → 내 단어 확인 → 설정 확인 → 일차 만들기 → 암기 (키보드) → 시험 → 결과와 시험 기록 → 홈의 진행률

## 5. 제한 사항

| 항목 | 값 | 시연에 미치는 영향 |
|------|-----|-------------------|
| 가입 | 같은 IP에서 1시간 20회 | 같은 Wi-Fi의 참가자는 공인 IP 하나를 함께 쓴다. 시연 참가자는 10명 이내라 조정하지 않는다 (2026-11-05 확정). 20명이 넘으면 가입이 막힌다 |
| 로그인 실패 | 계정과 IP 조합 15분 5회, IP 15분 50회 | 비밀번호를 여러 번 틀리면 기다려야 한다 |
| 단어장 담기·제외 | 요청 횟수 제한 없음 (M10에서 검토). 단어장은 운영자가 시연 전에 준비 | 참가자는 파일을 올리지 않는다. 표본 단어장은 4권 1,988개다 |
| ngrok 무료 플랜 | 월 1GB 전송, 2만 건 요청 | 리허설과 함께 쓴다 (D-W19) |

## 6. 리허설

시연 전에 한 번 실행한다. 터널이 열려 있는 동안에는 주소를 아는 누구나 접속할 수 있으므로 끝나면 바로 닫는다.

1. 서버를 실행한다 (§2).
2. 다른 터미널에서 자동 점검을 실행한다. 경고 페이지 통과, 가입부터 시험까지, Secure 쿠키, 닫힌 API 문서를 확인한다.
   ```
   .venv\Scripts\python ai-agent/scripts/demo_check.py https://시연주소
   ```
3. 서버 접속 기록에 `127.0.0.1`이 아닌 접속자 IP가 찍히는지 본다 (NFR-DEMO-04).
4. **Wi-Fi를 끈 휴대폰**(LTE/5G)으로 주소를 열어 가입부터 시험까지 해 본다. 구현 계획의 MD 완료 기준이다.
5. Ctrl+C로 닫고 시연 DB를 지운다 (§7).

**2026-11-05 결과: 통과.** 코드 수정은 없었다.

| 항목 | 결과 |
|------|------|
| 서버와 터널 실행 | 정상 |
| 자동 점검 (`demo_check.py`) | 16/16 통과 |
| 접속 기록의 IP | PC와 휴대폰이 각각 다른 IP로 찍힘 |
| Wi-Fi를 끈 휴대폰 | 가입부터 시험, 로그아웃까지 완료. 서버 오류 없음 |
| 정리 | 터널 닫힘, `reset`으로 시연 DB 삭제 |

확인하지 못한 것:

- **여러 명 동시 접속**: 기기 2대가 차례로 접속했다.
- **실제 터널에서의 로그인 잠금**: IP가 나뉘는 것까지 확인했다. 잠금 분리는 2026-11-04에 헤더로 수동 확인했다.

**시연 전 점검 (2026-11-05 실시)**:
- 실제 ngrok 터널로 `demo_check.py`가 17/17 통과했다 (단어장 담기 단계 포함).
- Ctrl+C로 서버와 터널이 함께 닫혔다. ngrok 프로세스와 8000·4040 포트가 사라졌고 이전 주소는 404를 돌려줬다. 종료 코드는 1이었는데, Ctrl+C가 같은 콘솔의 ngrok에도 전달되어 터널이 먼저 끝나는 경로를 탔기 때문이며 서버와 터널은 모두 닫혔다.
- 점검은 자동화 도구에서 Ctrl+C를 보내는 방식이었다. 사람이 터미널에서 누르는 경우와 완전히 같지는 않을 수 있어, **시연 직전에 직접 한 번 눌러 보고** 주소가 열리지 않는지 확인한 뒤 `reset`을 실행한다.

## 7. 끝난 뒤 정리

```
.venv\Scripts\python ai-agent/scripts/demo_server.py reset
```

- `data/smart_voca_demo.db`만 지운다. 터널이 열려 있으면 실행되지 않는다.
- 시연 전에도 실행해 리허설 기록과 가입 횟수 기록을 비운다.

## 8. 문제가 생기면

| 증상 | 확인할 것 |
|------|-----------|
| "ngrok 터널을 열지 못했습니다" | 출력된 로그 끝부분. 인증 토큰 미설정이면 `ngrok config add-authtoken 토큰` (토큰은 문서나 커밋에 적지 않는다) |
| "이미 열린 ngrok 터널이 있습니다" | 다른 터미널에 떠 있는 ngrok을 닫는다. 무료 플랜은 동시에 하나만 열 수 있다 |
| 서버가 바로 종료됨 | 8000번 포트를 쓰는 다른 프로그램, 개발 서버 |
| Ctrl+C 뒤에도 주소가 열림 | 작업 관리자에서 `ngrok.exe`와 시연 서버의 `python.exe`를 끝낸다 |
| 로그인이 안 되거나 바로 풀림 | 주소가 https인지. 시연 쿠키는 Secure라 http로는 저장되지 않는다 |
