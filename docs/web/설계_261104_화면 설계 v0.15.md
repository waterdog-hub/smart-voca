# smart-voca 웹 서비스 — 화면 설계

**파일 위치**: `docs/web/설계_261104_화면 설계 v0.15.md`
**작성일**: 2026-11-04
**버전**: v0.15 (문서 재검토 반영)
**설명**: 공개·회원 화면의 목록, 화면 구성, 사용자 흐름, 상태별 표시(빈 상태·오류·인증 전)를 정리한 5단계 설계 문서

---

## 1. 전제

- 결정 기록, 데이터 모델, 인증·보안 설계, API 설계의 최신 확정 사항을 따른다.
- 기존 데스크톱 화면(`src/gui/`: 단어장, 암기, 시험, 설정 탭과 대화상자 3개)의 기능을 웹 화면으로 옮긴다.
- 화면 배치의 실제 모습(색, 여백)은 이 문서 범위에서 제외한다. 필요하면 다음 단계에서 목업으로 만든다 (§9).

## 2. 탭 구조 → 페이지 구조

| 기존 (데스크톱) | 웹 | 이유 |
|-----------------|-----|------|
| 탭 4개 (단어장, 암기, 시험, 설정) | 좌측 메뉴 + 페이지 (홈, 단어장, 내 단어, 암기, 시험, 시험 기록, 설정, 내 계정) | 웹은 주소(URL)로 화면을 구분해야 새로고침·뒤로가기·공유가 된다 |
| 대화상자 (단어 수정, 일차 보기, 시험 기록) | 페이지 또는 같은 페이지 안의 패널 | 대화상자는 뒤로가기로 닫을 수 없다. 짧은 작업만 패널로 둔다 (단어 수정 패널은 공용 단어장 도입으로 없어졌다) |

**결정 (D-UI01)**: 페이지 구조를 쓴다. 기존 탭의 묶음은 메뉴 항목으로 그대로 옮긴다. 기존 탭의 단어장 탭은 공용 단어장 고르기(`/wordbooks`)와 읽기 전용 내 단어(`/words`)로 나뉜다 (D-WB08). 추가되는 것은 홈, 시험 기록, 내 계정이다.

## 3. 화면 목록

### 3.1 공개 화면 (로그인 전)

| ID | 화면 | 주요 요소 | 연결 API |
|----|------|-----------|----------|
| P-01 | 시작 (소개, `/`) | 서비스 소개, 로그인·가입 버튼. 로그인하지 않은 방문자에게 보여 주고, 회원은 홈(H-01)을 본다 | 없음 |
| P-02 | 로그인 | 이메일, 비밀번호, 로그인 버튼, 구글·카카오 버튼(키가 설정된 제공자만, 가입 화면에도 표시. 버튼 아래에 "처음 로그인하면 이용약관·개인정보 처리방침에 동의한 것으로 봅니다"), 소셜 실패 안내(`?social_error=` 코드를 문구로 바꿈, 알 수 없는 값은 표시하지 않음), 가입·재설정 링크. 탈퇴 직후(`?withdrawn=1`)에는 "탈퇴가 완료되었습니다" 안내 | `POST /auth/login`, `GET /auth/social/{p}/start` |
| P-03 | 가입 | 이메일, 비밀번호, 표시 이름, 이용약관·개인정보 처리방침 동의 체크 (필수) | `POST /auth/signup` |
| P-04 | 인증 메일 안내 (시연 환경은 가입 안내) | "메일을 보냈습니다", 로그인 화면 링크. 시연 환경은 메일이 없어 로그인을 안내한다. 재발송은 로그인 후 인증 안내 띠에서 한다 (D-UI07) | 없음 |
| P-05 | 인증 결과 | 성공 또는 실패 (만료·사용됨) 문구, 로그인 화면 이동. 같은 탭에 새 링크를 붙여 넣어도 다시 확인한다 | `POST /auth/verify-email` |
| P-06 | 재설정 요청 (`/forgot-password`) | 이메일 입력, "가입된 이메일이면 재설정 안내 메일을 보냈습니다" 문구 (가입 여부 노출 없음). 시연 환경은 "메일이 발송되지 않아 재설정할 수 없다, 새로 가입하라"는 안내. 로그인한 회원은 내 계정으로 이동 | `POST /auth/password-reset/request` |
| P-07 | 새 비밀번호 설정 (`/reset-password`) | 새 비밀번호, 확인 입력. 토큰은 주소 조각에서 읽어 주소창에서 지운다. 완료하면 잠시 뒤 로그인 화면으로 이동 | `POST /auth/password-reset/confirm` |
| P-08 | ~~계정 연결 확인~~ (별도 화면 없음) | 로그인한 상태가 이미 비밀번호 확인이므로 내 계정(A-01)의 연결 버튼과 비밀번호 입력으로 대신한다 (결정 D-M807). 인증 설계 §4.2 규칙 4 | `POST /auth/social/{p}/link` |
| P-09 | 소셜 가입 이메일 입력 (`/signup/social`) | 제공자에서 인증된 이메일을 받지 못했을 때 이메일 입력, "확인 메일 받기". 대기 상태(쿠키)가 없으면 로그인으로 이동 | `POST /auth/social/complete` |

## 4. 화면 구성 (와이어프레임)

### 4.1 회원 공통 틀
```
넓은 화면                                          좁은 화면 (휴대폰)
+------------+------------------------------+      +--------------------------+
| 🏠 홈      | (인증 전이면 안내 띠)        |      | (인증 전이면 안내 띠)    |
| 📚 단어장  | 페이지 제목                  |      | 페이지 제목              |
| 🃏 암기    | 알림 영역                    |      | 알림 영역                |
| ✏️ 시험    |                              |      |      (선택한 페이지)     |
| ────────── |    (선택한 페이지)           |      |                          |
| 📒 내 단어 |                              |      | ╭──────────────────────╮ |
| 🏅 시험 기록|                             |      | │홈 단어장 암기 시험 ✨│ |
| 🎨 설정    |                              |      | ╰──────────────────────╯ |
| 🙂 내 계정 |                              |      |  (더보기: 내 단어, 시험   |
| 이름 님    |                              |      |   기록, 설정, 내 계정,    |
| [로그아웃] |                              |      |   로그아웃)              |
+------------+------------------------------+      +--------------------------+
```
- 상단 바는 두지 않는다. 회원 이름과 로그아웃은 메뉴 아래쪽에 있다. 진행률은 홈(H-01)에서 보여 준다 (FR-PLAN-06). "내 계정"은 메뉴의 맨 아래 항목이다 (M7에서 추가).
- 인증 전이면 본문 위에 띠 배너: "이메일 인증이 필요합니다", [인증 메일 다시 받기]. 쓰기 버튼은 비활성처럼 보이게 하고(`aria-disabled`), 눌렀을 때 같은 안내를 띄운다.
- 좁은 화면(720px 이하)에서는 좌측 메뉴를 화면 아래에 떠 있는 둥근 탭 바로 바꾼다 (D-UI13). 홈·단어장·암기·시험과 "더보기"가 있고, 더보기를 누르면 내 단어·시험 기록·설정·내 계정과 이름·로그아웃이 열린다. 바깥을 누르거나 Esc를 누르면 닫힌다.
- 시연 환경(`APP_ENV=demo`)에서는 모든 화면의 머리글 아래에 실제 비밀번호와 개인정보를 쓰지 말라는 안내를 둔다 (D-W19).
- 메뉴에는 구현한 화면만 표시한다. 누르면 404가 나는 항목을 두지 않는다.
- 넓은 화면의 메뉴는 화면 높이에 고정한다. 긴 목록에서도 로그아웃 버튼이 보여야 한다.
- 알림 영역은 제목 바로 아래에 둔다. 긴 화면에서 알림이 화면 밖으로 나가지 않게 한다.

### 4.2 암기 (M-01)
```
일차: [3일차 ▼]   진행 12/20 ███████░░░░
+--------------------------------------------------+
|                    apple                         |
|                                                  |
|                [ 뜻 보기 ]                       |
|                                                  |
|   사과                                           |
+--------------------------------------------------+
|        [ 다시 ]              [ 외움 ]            |
+--------------------------------------------------+
```
- 뜻은 펼치기 전에는 가린다. 펼친 뒤 "외움" 또는 "다시"를 누른다.
- 키보드: 뜻 보기는 ↑ 또는 Space, 외움은 → 또는 1, 다시는 ← 또는 2다 (F-12, D-17, D-UI09). 버튼 글자에는 단축키를 적지 않고(사용자 요청, 2026-11-05), 화면 하단에 작은 안내 줄을 둔다. 화면 낭독기에는 버튼의 `aria-keyshortcuts`로 알린다.
- 뜻을 펼치기 전에는 외움·다시 버튼을 보여 주지 않는다.
- 모두 처리하면 요약 카드: 외운 수, 이번 접속에서 다시 본 횟수, 다음 일차 만들기 버튼. 다시 본 횟수는 저장하지 않는다.
- 다시 들어오면 첫 번째 미완료 카드부터 보여 준다. 뜻을 펼친 상태는 기억하지 않는다.
- 지난 일차를 고르면 복습 안내 띠를 보여 주고 모든 카드를 처음부터 보여 준다 (D-UI10). 요약에는 "처음부터 다시"와 "현재 일차로"를 둔다.

### 4.3 단어장 (W-04)와 내 단어 (W-01)
```
단어장                                   담은 단어장 1개 / 전체 4개
+-------------------------------------------------------+
| 초급 단어                                    [담음]   |
| 프로젝트 표본 단어 목록의 1~500번째 단어               |
| 단어 500개 · 예: abandon, ability, able, ...          |
| 출처: 프로젝트 표본 단어 목록 …              [제외]   |
+-------------------------------------------------------+
| 중급 단어                                              |
| ...                                          [담기]   |
+-------------------------------------------------------+
[ 내 단어 보기 ]
```
- 단어장은 운영자가 준비한 것만 보인다. 회원이 만들거나 고치지 못한다 (D-WB04).
- [담기]: 바로 담고 "새 단어 N개, 이미 있던 단어 M개는 건너뜀"을 알림 영역에 보여 준다.
- [제외]: 확인 창을 거친다. "다른 담은 단어장에 없는 단어는 학습과 진도에서 빠집니다. 학습 기록은 남고, 다시 담으면 이어집니다." 결과는 "빠진 단어 N개, 남긴 단어 M개"로 알린다.
- 인증 전이면 담기·제외는 안내 띠의 같은 안내를 띄운다 (§4.1). 요청이 겹치면 `409` 안내를 보여 준다.
- 단어장이 하나도 없으면 "준비된 단어장이 없습니다."를 보여 준다.
- 좁은 화면에서는 카드가 한 줄씩 쌓인다.

내 단어 (W-01)는 담은 단어를 보는 읽기 전용 화면이다.
```
[ 검색: ________ ]                         총 500개
+-------------------------------------------------------+
| 단어 ▲          | 뜻              | 등록일            |
+-------------------------------------------------------+
| apple           | 사과            | 2026-10-21        |
| run             | 달리다/운영하다 | 2026-10-21        |
+-------------------------------------------------------+
```
- 정렬은 열 제목을 누른다. 검색은 입력 후 짧게 기다렸다가 서버에 요청한다.
- 목록은 페이지 단위로 넘긴다 (API §1.4). 한 번에 50행.
- 비었으면 "아직 담은 단어가 없습니다"와 [단어장 고르기] 링크를 보여 준다.
- 좁은 화면에서는 표의 행을 카드로 바꾼다 (D-UI06).

### 4.4 시험 (T-01~T-03)
```
시험 준비
  형식: 객관식      방향: 영→한      문항 수: 20
  [ 시험 시작 ]
```
```
시험 3/20  ███░░░░
apple 의 뜻은?
  1) 사과   2) 달리다   3) 나무   4) 바다      (숫자키 1~4)
                         [ 다음 ]
```
- 제출 전에 확인 창: "아직 답하지 않은 문항이 2개 있습니다. 제출할까요?"
- 결과 화면에서 틀린 문항만 보기 버튼을 둔다.
- 시작: 형식과 방향의 기본값은 설정을 따른다. 문항 수는 1~200이고 기본 10이다. 객관식은 단어 4개, 주관식은 1개가 필요하다.
- 진행 중인 시험이 있으면 시작 화면에 "이어서 보기"를 두고, 새로 시작할 때 "진행 중인 시험을 그만두고 새로 시작할까요?"를 묻는다 (D-23).
- 키보드: 1~4 보기 선택, Enter 다음 문항과 제출 (D-17). 보기를 골라도 자동으로 넘어가지 않아 답을 고칠 수 있다. 주관식 입력칸에서 숫자는 글자다 (D-UI02).
- 답안은 제출할 때까지 브라우저 탭(`sessionStorage`)에 둔다. 새로고침과 세션 만료 후 복귀에서 문항과 답이 복원된다. 탭을 닫거나 다른 기기로 옮기면 문제만 복원된다.
- 답하지 않은 문항은 결과에 "(답 없음)"으로 표시한다. 점수에서는 오답이고 오답 횟수는 올리지 않는다 (API §6).
- 제출한 시험을 다시 열면 점수만 보여 준다. 폐기된 시험은 안내와 새 시험 링크를 보여 준다.

### 4.5 설정 (S-01)
- 숫자 입력칸마다 최소값을 칸 아래에 적는다. 예: "1 이상".
- 값이 잘못되면 저장 버튼을 누르기 전에 칸 아래에 바로 안내한다 (서버 검증과 같은 규칙). 안내 문구는 "1 이상 9999 이하로 입력해 주세요."다.
- 칸 목록과 범위는 서버(`setting_service.COUNT_FIELDS`)가 템플릿에 넘기고, 자바스크립트는 입력칸의 `min`, `max`를 읽는다. 규칙을 두 곳에 적지 않는다.
- 저장과 되돌리기는 값을 불러온 뒤에 켠다. 빈 칸을 저장하는 일을 막는다.
- 되돌리기는 마지막으로 저장한 값으로 복원하고 칸 안내와 알림을 지운다.
- 저장하면 "설정을 저장했습니다. 하루 분량은 다음 일차 진도부터 적용됩니다."를 띄운다. 이미 만든 일차는 바뀌지 않는다고 화면에 적는다.
- 인증 전에도 값을 볼 수 있다. 저장은 §4.1의 규칙대로 안내만 띄운다.
- 저장은 자바스크립트로 JSON API를 호출한다. 서버 폼을 따로 두면 같은 검사 경로가 둘이 되기 때문이다 (D-UI08과 같은 이유).

### 4.6 내 계정 (A-01)
```
내 계정
  이메일: learner@example.com
  [ 표시 이름 ____ ] [이름 저장]
  ── 비밀번호 변경 ──  [ 현재 ___ ] [ 새 ___ ] [비밀번호 바꾸기]
  ── 모든 기기에서 로그아웃 ──  [모든 기기에서 로그아웃]
  ── 탈퇴 ──  [ 비밀번호 ___ ] [ "탈퇴" 입력 ___ ] [탈퇴하기]
```
- 항목은 한 칸으로 쌓이고 375px에서도 가로 스크롤이 없다. 이름 저장은 인증 후에만 된다.
- 이름을 저장하면 메뉴의 이름도 바로 바뀐다. 현재 비밀번호가 틀리면 그 칸 아래에 안내한다.
- 소셜 연결 영역은 키가 설정된 제공자가 있을 때만 보인다. 제공자마다 "연결됨 / 연결 안 됨"과 [연결]·[해제] 버튼이 있고, 비밀번호가 있는 계정은 연결 전에 비밀번호 칸을 채운다. 연결이 끝나면 "소셜 계정을 연결했습니다", 실패하면 코드별 안내가 나온다. 마지막 로그인 수단의 해제는 서버가 막고 안내한다.
- 비밀번호가 없는 소셜 전용 계정은 "현재 비밀번호" 칸 대신 안내를 보이고, 제목과 버튼이 "비밀번호 설정"이 된다. 탈퇴는 비밀번호를 설정한 뒤에 할 수 있다.
- 탈퇴는 "탈퇴"를 입력하지 않으면 요청을 보내지 않고, 입력 뒤에도 확인 창과 비밀번호를 거친다. 완료하면 로그인 화면에 안내를 띄운다.
- 탈퇴는 가장 아래에 두고, 버튼을 누르면 "단어장·진도·기록이 모두 삭제되며 되돌릴 수 없습니다" 확인과 비밀번호 입력을 요구한다.
- 소셜 계정 연결 상태를 "연결됨 / 연결 안 됨"으로 표시하고, 마지막 로그인 수단은 해제 버튼을 비활성화한다 (API §2 `LAST_LOGIN_METHOD`).

## 5. 사용자 흐름

### 5.1 처음 쓰는 사람
```
P-01 → P-03 가입 → P-04 인증 메일 안내 → (메일 링크) → P-05 인증 완료
  → H-01 홈 (빈 상태: "단어장부터 담으세요")
  → W-04 단어장 (담기) → W-01 내 단어 확인 → S-01 설정 확인
  → H-01 "다음 일차 만들기" → M-01 암기 → T-01 시험 → T-03 결과
```

### 5.2 돌아온 사람
- 로그인 → H-01: 현재 일차 완료율과 "이어서 암기하기" 버튼. 첫 번째 미완료 카드부터 이어 간다 (D-10).

### 5.3 세션 만료
- 요청이 `401`을 받으면 로그인 화면(P-02)으로 보내고, 로그인 후 원래 페이지로 돌아가게 한다 (`/login?next=`). 같은 사이트 주소만 따르고 나머지는 홈으로 보낸다. 직접 로그아웃한 경우에는 돌아가지 않는다.
- 시험을 보는 중이었다면 시험 문제는 서버에 남아 있으므로 `GET /tests/{id}`로 복원한다 (API §6).

### 5.4 소셜 로그인
- 구글·카카오 버튼 → 제공자 화면 → 콜백. 연결된 계정이거나 인증된 이메일을 받으면 홈, 이메일을 못 받으면 P-09(이메일 입력 → 확인 메일 → 링크 → 소셜 로그인), 실패하면 로그인 화면의 안내. 같은 이메일 계정이 있어도 인증되지 않은 이메일은 자동 연결하지 않으며, 그 회원이 로그인해 A-01에서 연결한다.

## 6. 상태별 표시

| 상태 | 표시 방식 |
|------|-----------|
| 로딩 | 새 결과가 올 때까지 이전 목록을 그대로 두고 `aria-busy`로 알린다. 스켈레톤은 쓰지 않는다. 저장 버튼은 요청 중 비활성 (중복 클릭 방지, D-API05). |
| 빈 상태 | 단어장, 진도, 시험 기록에 각각 다음 할 일 안내 문구 |
| 입력 오류 | 해당 칸 아래 `!` 표시와 한글 안내 (색만으로 구분하지 않음). 칸 테두리 색과 `aria-invalid`도 바꾼다 |
| 서버 오류 | 제목 바로 아래 알림 영역 (`role="alert"`, 사라지는 토스트를 쓰지 않음). 화면 입력값은 지우지 않는다 |
| 인증 필요 | 띠 배너 + 쓰기 버튼 비활성 + 누르면 안내 |
| 충돌 (`409`) | 예: "잠시 후 다시 시도해 주세요"(단어장 담기·제외 겹침) 또는 "다음 일차를 만들 수 없습니다. 오늘 진도를 먼저 끝내세요" |
| 시험 불가 (`422`) | 시험 시작 버튼 비활성, 이유 표시 (단어 수 부족 등) |

## 7. 접근성 기준

- 모든 입력칸에 라벨을 둔다. 자리표시자 글자만으로 이름을 대신하지 않는다.
- 키보드만으로 모든 기능을 쓸 수 있어야 한다 (Tab 순서, 포커스 표시).
- 결과와 오류는 화면 낭독기가 읽을 수 있게 알림 영역에 표시한다.
- 글자와 배경의 대비는 WCAG AA (4.5:1) 이상. 테마 6가지 모두 같은 기준으로 색을 정했다 (§4.7). 자동 검사 도구로는 확인하지 않았고 계산과 스크린샷으로 확인했다.
- 움직임이 있는 장식은 `prefers-reduced-motion`을 따른다.

## 8. 설계 결정 (ADR 형식)

### D-UI01 페이지 구조 (탭 대신)
- **배경**: 웹은 URL로 화면을 구분해야 한다 (§2).
- **대안**: 한 화면에 탭 유지. 새로고침하면 탭 상태가 사라져 제외.

### D-UI02 암기·시험 화면의 키보드 단축키 유지
- **근거**: 기존 데스크톱 기능 (F-12, D-17). 같은 단축키로 익숙한 흐름을 유지한다.
- **주의**: 입력칸에 커서가 있을 때는 단축키가 동작하지 않게 한다 (글자 입력과 충돌 방지).

### D-UI03 제출 전 확인과 제외 확인
- **근거**: 시험 제출과 단어장 제외(단어가 진도에서 빠짐)는 되돌리기 어렵다 (기존 동작 유지).

### D-UI04 단어 수정은 패널로 (폐기: 회원 단어 수정 기능 삭제, D-WB04)
- **근거**: 목록 맥락을 잃지 않고 빨리 고칠 수 있다. 대화상자보다 뒤로가기 흐름과 충돌이 적다.

### D-UI07 인증 메일 재발송은 로그인 후 (v0.2)
- **배경**: P-04는 가입 직후 화면인데, 가입은 자동 로그인이 없고 (D-A04) 재발송 API는 로그인이 필요하다. 두 규칙이 충돌했다.
- **대안**: 이메일을 받는 공개 재발송 API (요청 횟수 제한과 응답 통일을 또 만들어야 함).
- **결과**: P-04에는 로그인 안내를 두고, 재발송 버튼은 §4.1의 인증 안내 띠에 둔다.

### D-UI08 인증 폼도 자바스크립트로 JSON API를 호출 (v0.4)
- **배경**: D-UI05는 암기·시험·단어장 외에는 서버가 HTML을 그리도록 정했다. 인증 폼을 서버 폼으로 처리하면 같은 인증 규칙의 경로가 둘이 된다.
- **대안**: 서버 폼 처리를 따로 구현.
- **결과**: 폼은 작은 자바스크립트로 API를 호출해 인증 처리 경로를 하나로 둔다. 인라인 스크립트를 쓰지 않아 CSP `script-src 'self'`와 충돌하지 않는다. 자바스크립트가 꺼진 환경은 지원하지 않는다.

### D-UI09 암기 단축키는 방향키와 Space, 1, 2를 함께 지원 (v0.5, 사용자 확정)
- **배경**: §4.2의 그림은 Space, 1, 2였고 본문과 기획서 F-12는 방향키였다. M5 전에 정해야 했다.
- **대안**: 방향키만 (기존 앱과 같음), Space, 1, 2만 (기획서 변경 필요).
- **결과**: 둘 다 지원한다. 같은 동작을 두 키가 호출하므로 규칙은 하나다. 뜻을 펼치기 전에는 외움과 다시 키가 동작하지 않는다.
- **구현 주의**: Space와 방향키는 브라우저 기본 스크롤을 막는다. 버튼이나 링크에 포커스가 있으면 Space는 그것을 누르는 키로 두어, 한 번 눌러 두 번 처리되지 않게 한다. D-UI02의 입력칸 예외(일차 선택 포함)를 그대로 적용한다. 키를 누르고 있어 반복되는 입력은 무시한다.

### D-UI11 디자인은 아기자기하고 귀여운 학습 앱 (v0.13, 사용자 요청, 이슈 #21)
- **배경**: 기존 화면은 회색 바탕의 실용적인 모양이었다. 사용자가 화면 구성까지 바꾸는 "밝고 친근한 학습 앱"을 원했고, 이어서 아기자기하고 귀여운 방향(고양이 마스코트, 테마 색 6가지, 책 아이콘, 발바닥 커서, 귀여운 글꼴)을 정했다.
- **대안**: 색·글꼴만 바꾸기(위험이 작지만 구성이 그대로), 미니멀, 다크 모드 중심.
- **결과**: §4.7. 기능과 API는 그대로다. 다크 모드는 범위 밖이다. 값은 CSS 변수에 모아 한곳에서 바꾼다.

### D-UI12 테마 선택은 브라우저에만 저장 (v0.13)
- **근거**: 개인 취향이라 서버에 둘 이유가 없고, 저장소를 못 쓰는 환경에서는 기본 색으로 보인다. 서버 저장은 하지 않는다.

### D-UI13 휴대폰 메뉴는 하단 탭 바 (v0.13)
- **배경**: 메뉴가 8개라 위쪽 메뉴가 줄바꿈되어 본문을 밀어냈다.
- **결정**: 720px 이하에서 하단 탭 바(홈·단어장·암기·시험·더보기)로 바꾸고 나머지는 더보기에 둔다. 앱처럼 엄지로 쓸 수 있다.
- **영향**: 내 단어·시험 기록·설정·내 계정은 더보기를 거친다. 메뉴 링크의 `<a href aria-current>` 형태는 유지한다.

### D-UI14 글꼴은 직접 제공 (v0.13)
- **대안**: 구글 폰트 서비스 (접속 정보가 외부로 나가고 보안 헤더 설정이 복잡해진다), 시스템 글꼴만 사용.
- **결정**: 오픈 글꼴(주아, 고운돋움)에서 글자를 줄인 파일을 직접 제공한다. 줄이는 도구는 `ai-agent/scripts/make_fonts.py`다 (개발용 패키지 `fonttools`, `brotli`).

### D-UI10 드롭다운으로 지난 일차 복습, 기록은 바꾸지 않음 (v0.7)
- **배경**: M-01의 일차 드롭다운과 D-16의 읽기 전용이 충돌했다. 사용자가 드롭다운으로 복습을 허용하기로 했다.
- **대안**: 현재 일차만 보여 주고 M-02로 연결, 복습에서도 외운 횟수와 날짜 갱신.
- **결과**: 지난 일차도 카드로 본다. 외움과 다시는 화면 안의 순서만 바꾸고 서버를 호출하지 않는다. `done`, `position`, 진행률, 다음 일차의 복습 후보가 바뀌지 않아 D-16의 "지난 진도는 바꾸지 않는다"를 지킨다. 복습 횟수는 남지 않고 새로고침하면 처음부터 시작한다 (2026-11-04 사용자 확정, 이슈 #14).
