## 1. 전제

- 기준 문서는 구현 계획 §6이다. 이 문서는 그 구성을 실제 테스트 파일과 결과로 구체화한다.
- 자동 테스트는 임시 폴더의 SQLite를 쓰며 `data/`를 바꾸지 않는다.
- 실행 명령 (프로젝트 루트): `.venv\Scripts\python -m unittest discover -s tests`

## 3. 마일스톤별 완료 기준과 결과

완료 기준은 구현 계획 §5에서 가져왔다.

| 마일스톤 | 완료 기준 | 근거 테스트 | 결과 |
|----------|-----------|-------------|------|
| M0 준비 | 앱이 뜨고 `/healthz`가 200. 기존 59개 통과 | `test_health_api.py` | 통과 |
| M1 DB 기반 | 빈 DB에 마이그레이션 적용·되돌리기. DB 연결 실패 시 `/healthz` 503 | `test_migrations.py`, `test_health_api.py` | 통과 |
| M2 인증 | 인증 API 테스트 통과. 미인증 쓰기 요청 403 | `test_auth_api.py`, `test_security.py` | 통과 |
| M3 단어장 | 중복, 대소문자, 소프트 삭제, 이름 변경 규칙 통과 | `test_words_api.py`, `test_words_csv.py`, `test_isolation.py` | 통과 |

M2까지의 쓰기 차단은 시험용 주소로 확인했고, M3부터 실제 단어 쓰기 API로 확인한다.

## 4. 브라우저 점검 목록

자동 테스트는 자바스크립트를 실행하지 않으므로 아래 항목은 실제 브라우저로 확인한다. M2, M3 때 실제 uvicorn, 마이그레이션한 임시 DB, 헤드리스 Chrome으로 확인했다 (M2 20개, M3 39개 항목). 사용한 스크립트는 일회성이어서 저장소에 없다.

### 4.1 인증 (M2)
- [x] 로그인 없이 회원 화면을 열면 로그인 화면으로 이동한다
- [x] 흔한 비밀번호로 가입하면 칸 아래에 오류가 나오고 버튼이 다시 활성화된다
- [x] 가입 후 인증 메일 안내 화면으로 이동한다
- [x] 잘못된 비밀번호는 안내 문구를 보여 주고, 맞는 비밀번호는 홈으로 이동한다
- [x] 세션 쿠키는 자바스크립트에서 읽을 수 없다
- [x] 1분 안의 재발송은 남은 시간을 안내한다
- [x] 메일 링크로 인증이 끝나고, 주소창과 서버 접속 로그에 토큰이 남지 않는다
- [x] 사용한 링크를 다시 열면 실패 문구가 나온다 (새 로드, 같은 탭 붙여넣기 모두)
- [x] 인증 후 안내 띠가 사라지고, 로그아웃 후 회원 화면이 막힌다

### 4.2 단어장 (M3)
- [x] 인증 전에는 쓰기 버튼이 비활성으로 보이고, 누르면 인증 안내가 나온다
- [x] 빈 단어장 안내와 검색 결과 없음 안내가 구분된다
- [x] 추가, 대소문자 중복 오류, 수정(뜻 정리 포함), 삭제 취소와 확인이 동작한다
- [x] 단어에 넣은 HTML이 실행되지 않고 글자로 보인다
- [x] 표본 단어장 `data/words.csv`(1,988개)를 가져와 개수가 맞는다 (약 0.3초)
- [x] 페이지 이동, 열 정렬, 단어·뜻 검색이 동작한다
- [x] 수정 패널을 열면 첫 칸에 포커스가 가고, Esc로 닫으면 포커스가 돌아온다
- [x] 첫 줄이 틀린 파일은 안내 문구를 보여 준다
- [x] 내보내기 파일이 BOM과 머리글로 시작한다

### 4.3 화면 공통
- [x] 375px 폭에서 가로 스크롤이 없다

- [x] 긴 목록에서 스크롤 전후 모두 로그아웃 버튼이 보인다
- [x] 짧은 화면에서 메뉴와 본문 사이가 벌어지지 않는다

## 5. 검증하지 못한 범위

| 범위 | 현재 상태 | 확인 시점 |
|------|-----------|-----------|
| PostgreSQL | 모든 테스트가 SQLite. PostgreSQL용 DDL 생성만 확인했고 실행은 안 함. 드라이버 미설치 | M10 전 |
| 실제 메일 발송 | 개발용 콘솔 출력과 기록용 구현만 확인. 운영 구현 없음 | M10 |
| 프록시 환경 | 프록시 헤더, 요청 크기 제한, HTTPS, Secure 쿠키의 실제 전송 미확인 | M10 |
| 동시 요청 | 충돌 처리는 시점을 조작해 확인했고 실제 병렬 부하는 안 함 | M10 |
| CHECK 제약 변경 | `alembic check`가 감지하지 못함 (구현 계획 D-IMP10). 수동 작성 필요 | 변경 시마다 |
| 회귀 자동화 | 브라우저 점검은 자동 테스트 명령에 포함되지 않음. §4를 마일스톤마다 다시 확인 | 마일스톤마다 |
