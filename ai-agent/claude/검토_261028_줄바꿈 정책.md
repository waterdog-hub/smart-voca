# 검토 — 줄바꿈 경고 해결 방식

**파일 위치**: `ai-agent/claude/검토_261028_줄바꿈 정책.md`
**작성일**: 2026-10-28
**설명**: 커밋할 때마다 나오는 CRLF/LF 경고를 없애는 방식을 비교하고 결정 근거를 남긴 문서 (설계 결정 기록)

---

## 1. 배경

- 저장소의 파일은 모두 LF로 커밋되어 있다 (`git ls-files --eol`에서 `i/lf`).
- 이 PC의 전역 Git 설정은 `core.autocrlf=true`다 (`C:/Program Files/Git/etc/gitconfig`).
- 그래서 작업 폴더 파일이 CRLF로 체크아웃되고, `git add` 때마다 "LF will be replaced by CRLF" 경고가 나온다.
- 실제 데이터 손상은 없다. 경고만 반복된다. 현재 `data/words.csv`만 작업 폴더가 CRLF다 (커밋 내용은 LF).

## 2. 시험한 방법 (임시 복사본에서만 실행, 저장소는 변경하지 않음)

| 방법 | 설정 위치 | 결과 |
|------|-----------|------|
| A. `.gitattributes`에 `* text=auto eol=lf` | 저장소 파일 | 경고 계속 남음 (작업 폴더가 CRLF일 때). 정책 파일이 하나 늘어남 |
| B. `.gitattributes`에 `* text=auto` | 저장소 파일 | 경고 계속 남음 |
| C. 저장소 설정 `core.autocrlf=input` + LF로 체크아웃 | 이 저장소의 `.git/config` (로컬) | **경고 없음**, 상태 깔끔 |
| D. 전역 설정 `core.autocrlf` 변경 | PC 전체 | 다른 저장소에도 영향. 사용하지 않음 |

- 방법 C는 체크아웃을 LF로 다시 받은 뒤에만 경고가 사라졌다. 체크아웃 전에 설정만 바꾸면 경고가 남는다.

## 3. 대안 비교

| 항목 | A (`.gitattributes`) | C (저장소 로컬 설정) |
|------|----------------------|----------------------|
| 경고 제거 | 안 됨 (이 PC에서) | 됨 |
| 저장소에 파일 추가 | 필요 | 불필요 |
| 다른 PC와의 일관성 | 높음 (정책이 커밋됨) | 이 PC 한정 |
| 되돌리기 | 파일 삭제 | `git config --unset core.autocrlf` |
| 기존 파일 영향 | 재정규화 가능성 | 없음 (커밋된 내용은 그대로) |

## 4. 결정 (제안)

- **방법 C를 쓴다.** 저장소 로컬 설정 `core.autocrlf=input`을 적용하고, 작업 폴더를 LF로 다시 맞춘다.
- 전역 설정은 바꾸지 않는다.
- `.gitattributes`는 지금 추가하지 않는다. 다른 PC에서 같은 경고가 나오면 그때 추가를 검토한다.

## 5. 적용 절차 (승인 후 실행)

1. `git config core.autocrlf input` (이 저장소 로컬 설정)
2. 작업 폴더의 CRLF 파일을 LF로 바꾸기 위해 `git checkout -- <파일>`로 다시 받기 (커밋된 내용 기준, 변경 없는 파일만 대상)
3. 확인: `git status`가 깨끗하고, 경고가 나오지 않는지 `git add`로 확인
4. 결과를 일지에 기록

**주의**: 2번은 작업 폴더의 파일을 다시 받는다. 커밋되지 않은 변경이 있으면 먼저 커밋하거나 보관해야 한다. 현재 작업 트리는 깨끗하다 (2026-10-28 push 후).

## 6. 영향 범위

- 커밋 내용과 기록은 바뀌지 않는다.
- 코드 동작에 영향이 없다. CSV 읽기와 쓰기는 줄바꿈 방식과 무관하다.
- `data/words.csv` 등 개인 데이터 파일도 내용은 그대로이고 줄바꿈만 바뀐다.

## 7. 기록: D-24 대소문자만 다른 단어 (확정, 사용자 결정)

- **배경**: `Apple`과 `apple`이 서로 다른 단어로 저장되어, 같은 단어가 두 번 들어갈 수 있었다.
- **결정**: 대소문자만 다르면 같은 단어로 본다. CSV 불러오기는 뒤에 나온 행을 건너뛰고, 단어 추가·수정은 중복이면 거부한다. 자기 자신의 대소문자만 바꾸는 수정은 허용한다.
- **구현**: `WordRepository.load()`의 중복 검사, `WordService.validate()`.
- **기록 위치**: 설계서는 승인된 문서이므로 다음 설계 버전에서 D-24로 정식 반영한다.

## 8. 적용 결과 (2026-10-28, 사용자 승인)

- `git config core.autocrlf input`을 이 저장소 로컬 설정으로 적용했다. 전역 설정은 그대로다.
- 작업 폴더에 CRLF로 남아 있던 `data/words.csv`를 커밋된 내용으로 다시 받았다. 내용은 커밋본과 같다.
- 확인: 추적 파일 50개 모두 LF, 작업 트리 깨끗함, 테스트 56개 통과.
- 이 문서는 아직 커밋하지 않았다.
