# smart-voca 웹 서비스 — API 설계

**파일 위치**: `ai-agent/claude/261104_웹서비스 전환/설계_261104_API 설계 v0.1.md`
**작성일**: 2026-11-04
**버전**: v0.1 (초안, 사용자 확인 전)
**설명**: 회원·단어장·설정·진도·암기·시험 기능을 REST JSON API로 나누고, 권한·오류 형식·시험 정답 보호 규칙을 정리한 4단계 설계 문서

---

## 1. 전제와 공통 규칙

- 결정 기록 v0.1, 데이터 모델 v0.1, 인증·보안 설계 v0.1의 확정 사항을 따른다.
- 기존 핵심 로직(`src/core/`)의 기능을 API로 옮긴다. 화면 흐름은 5단계(화면 설계)에서 정한다.
- 기본 경로: `/api/v1`. 모든 요청·응답은 JSON (`application/json`, 단어장 가져오기·내보내기만 예외).
- 날짜·시각은 ISO 8601 UTC 문자열 (`2026-11-04T06:30:00Z`). 화면에서 한국 시간으로 바꾼다 (데이터 모델 D-W11).
- ID는 정수. 다른 회원의 자원 ID를 넣으면 `404`를 응답한다 (D-A09).

### 1.1 인증과 권한 수준

| 수준 | 조건 | 대상 |
|------|------|------|
| 공개 | 로그인 불필요 | 가입, 로그인, 인증 메일 확인, 재설정, 소셜 시작·콜백 |
| 로그인 | 유효한 세션 쿠키 | 내 정보 조회, 로그아웃, 계정 설정 |
| 인증 완료 | 로그인 + `email_verified_at` 있음 | 단어·설정 쓰기, 진도 생성, 암기, 시험 (인증 설계 §3.4) |

- 로그인 상태만 있고 인증이 안 된 회원이 쓰기 요청을 보내면 `403 EMAIL_NOT_VERIFIED`.
- 읽기 요청(단어 목록, 진도 조회, 시험 기록 조회)은 로그인만 있으면 된다.

### 1.2 CSRF

- 상태를 바꾸는 요청(POST, PUT, PATCH, DELETE)은 헤더 `X-CSRF-Token`을 함께 보낸다 (D-A07).
- 토큰은 `GET /auth/session` 응답으로 받는다. 로그인 세션마다 하나씩 발급한다.
- 토큰이 없거나 다르면 `403 CSRF_INVALID`.

### 1.3 오류 응답 형식

```
{ "error": { "code": "WORD_DUPLICATE", "message": "이미 있는 단어입니다.", "fields": { "word": "..." } } }
```

- `code`는 고정된 영문 값이라 화면이 분기에 쓴다. `message`는 사용자에게 보여줄 한글 문구다.
- `fields`는 입력 검증 오류일 때만 쓴다.

| HTTP | code 예시 | 상황 |
|------|-----------|------|
| 400 | `VALIDATION_FAILED` | 입력 형식·범위 오류 |
| 401 | `AUTH_REQUIRED` | 로그인 필요 |
| 403 | `EMAIL_NOT_VERIFIED`, `CSRF_INVALID` | 권한 또는 CSRF 실패 |
| 404 | `NOT_FOUND` | 없거나 다른 회원의 자원 |
| 409 | `WORD_DUPLICATE`, `PLAN_NOT_READY`, `TEST_ALREADY_SUBMITTED` | 상태 충돌 |
| 413 | `FILE_TOO_LARGE` | 가져오기 파일 5MB 초과 |
| 422 | `TEST_NOT_POSSIBLE` | 단어 수 부족 등 시험을 만들 수 없음 |
| 429 | `RATE_LIMITED` | 요청 횟수 초과 |

### 1.4 목록 공통 규칙

- 목록은 `limit`(기본 50, 최대 200)과 `offset`으로 나눈다. 단어장은 수천 개가 될 수 있다.
- 응답 형식: `{ "items": [...], "total": 1988 }`.

## 2. 인증·계정 API

| 메서드·경로 | 권한 | 설명 | 주요 응답·규칙 |
|-------------|------|------|----------------|
| `POST /auth/signup` | 공개 | 가입 (이메일, 비밀번호, 표시 이름, 약관·개인정보 동의) | `202`, 중복 여부와 관계없이 같은 응답. 자동 로그인 없음. 신규면 인증 메일, 기존 회원이면 "이미 가입된 이메일" 안내 메일 발송 (인증 설계 D-A04). 동의 안 하면 `400` |
| `POST /auth/social/complete` | 가입 대기 | 소셜 가입에서 이메일 입력 (제공자가 이메일을 주지 않은 경우) | `202`, 인증 메일 발송. 인증이 끝나면 회원 생성 (데이터 모델 v0.2 §4.3). 가입 대기 세션이 없으면 `401` |
| `POST /auth/login` | 공개 | 로그인 | 세션 쿠키 발급. 실패는 `401 LOGIN_FAILED` (이메일 존재 여부 숨김). 잠금 중이면 `429` |
| `POST /auth/logout` | 로그인 | 현재 세션 종료 | `204` |
| `POST /auth/logout-all` | 로그인 | 모든 기기 세션 종료 | `204`, 현재 세션도 종료 |
| `GET /auth/session` | 공개 | 현재 상태 확인 (로그인 여부, 인증 여부, CSRF 토큰) | 로그인 안 했으면 `{ "user": null }` |
| `POST /auth/verify-email` | 공개 | 인증 메일 링크 값 확인 | 토큰 만료·재사용은 `400 TOKEN_INVALID` |
| `POST /auth/resend-verification` | 로그인 | 인증 메일 재발송 | 1분에 1회 제한 |
| `POST /auth/password-reset/request` | 공개 | 재설정 메일 요청 | 가입 여부와 관계없이 `202` 동일 응답 (D-A04) |
| `POST /auth/password-reset/confirm` | 공개 | 새 비밀번호 설정 | 성공 시 모든 세션 종료 |
| `GET /auth/social/{provider}/start` | 공개 | 소셜 로그인 시작 (`provider`: `google`, `kakao`) | 제공자 인증 페이지로 이동 (302). `state`, PKCE 값 발급 |
| `GET /auth/social/{provider}/callback` | 공개 | 제공자 콜백 | 계정 연결 규칙 (인증 설계 §4.2). 수동 연결이 필요하면 연결 화면으로 이동 |
| `POST /auth/social/{provider}/link` | 로그인 | 비밀번호 확인 후 소셜 계정 연결 | 확인 실패는 `401` |
| `DELETE /auth/social/{provider}` | 인증 완료 | 소셜 연결 해제 | 비밀번호가 없고 연결도 마지막이면 `409 LAST_LOGIN_METHOD` |
| `GET /me` | 로그인 | 내 정보 | 이메일, 표시 이름, 인증 여부, 연결된 소셜 목록 |
| `PATCH /me` | 인증 완료 | 표시 이름 변경 | |
| `POST /me/password` | 인증 완료 | 비밀번호 변경. 소셜 전용 계정은 현재 비밀번호 없이 새 비밀번호 설정 가능 | 비밀번호가 있으면 현재 값 확인. 성공 시 다른 세션 종료 |
| `DELETE /me` | 인증 완료 | 탈퇴 (비밀번호 확인, 소셜 전용 계정은 제공자 재로그인으로 확인) | 하드 삭제: 회원 데이터 전부 삭제, 세션 종료 (데이터 모델 v0.2 §4.4) |

### 2.1 로그인 실패 응답 규칙
- 잘못된 이메일과 잘못된 비밀번호를 같은 `LOGIN_FAILED`로 응답한다.
- 응답 시간 차이를 줄이기 위해 존재하지 않는 이메일도 해시 검증 시간을 쓴다 (구현 시 확인).

## 3. 단어장 API

| 메서드·경로 | 권한 | 설명 | 주요 규칙 |
|-------------|------|------|-----------|
| `GET /words` | 로그인 | 단어 목록 | 쿼리: `q`(단어·뜻 검색), `sort`(`word`, `meaning`, `created`), `order`(asc/desc), `limit`, `offset`. 삭제되지 않은 단어만 |
| `POST /words` | 인증 완료 | 단어 추가 | `word`, `meaning`. 같은 `word_key`가 있으면 `409 WORD_DUPLICATE` (D-24). 뜻 빈칸은 `400` |
| `PATCH /words/{id}` | 인증 완료 | 단어·뜻 수정 | 이름 변경도 중복 검사. 기록·진도는 `word_id`로 연결돼 그대로 유지 (D-13) |
| `POST /words/delete` | 인증 완료 | 단어 삭제 (여러 개 가능) | 본문: `{ "ids": [..] }`. 소프트 삭제 + 진도 행 삭제 (D-W07, D-12). 응답: 삭제 개수 |
| `POST /words/import` | 인증 완료 | CSV 가져오기 | `multipart/form-data`, 5MB·5,000행 이하 (인증 설계 §5). 응답: `{ added, skipped_duplicate, skipped_invalid }` (D-14) |
| `GET /words/export` | 로그인 | CSV 내보내기 | `text/csv; charset=utf-8` (BOM 포함). 수식 주입 방지 (`'` 접두) |

- 가져오기는 한 트랜잭션으로 처리한다 (데이터 모델 §4.3). 실패하면 아무것도 저장하지 않는다.
- 기존 D-22(가져오기 전 자동 백업)의 대체 방식은 웹에서 다르게 정한다. 회원별 단어장 내보내기(`GET /words/export`)와 서버 DB 백업을 6단계 배포 설계에서 확정한다.

## 4. 설정 API

| 메서드·경로 | 권한 | 설명 | 주요 규칙 |
|-------------|------|------|-----------|
| `GET /settings` | 로그인 | 설정 조회 | 회원 가입 때 만든 기본값 |
| `PUT /settings` | 인증 완료 | 설정 전체 저장 | 허용 값과 최소값 검사 (D-23). `daily_new_count >= 1`. 범위를 벗어나면 `400` + `fields` |

- `current_day`는 클라이언트가 보낼 수 없다. 서버만 진도 생성 때 바꾼다 (데이터 모델 D-W10).

## 5. 진도 API (일차별 진도, 암기)

| 메서드·경로 | 권한 | 설명 | 주요 규칙 |
|-------------|------|------|-----------|
| `GET /plans` | 로그인 | 일차 목록 (일차별 요약: 단어 수, 완료 수) | 지난 일차 보기 (F-11, D-16) |
| `GET /plans/{day}` | 로그인 | 한 일차의 항목 (단어, 유형 new/review/wrong, 완료 여부, 순서) | 읽기 전용. `position` 순 |
| `POST /plans` | 인증 완료 | 다음 일차 생성 (`current_day + 1`) | 생성 조건을 만족하지 않으면 `409 PLAN_NOT_READY` (D-08, D-18). 응답: 생성된 일차 |
| `PATCH /plan-items/{id}` | 인증 완료 | 암기 완료 표시 `{ "done": true/false }` | 완료 시 `study_records.memorized_count` +1, `first_memorized_day`, `last_memorized_date` 갱신 (설계 6.4) |
| `GET /progress` | 로그인 | 진행률 요약 (전체 단어 수, 암기한 단어 수, 현재 일차 완료율) | 진행률 표시 (D-17) |

- 같은 항목에 `done: true`를 두 번 보내도 결과가 같아야 한다 (멱등). 카운트를 두 번 올리지 않는다.
- 카드 위치 복원 (D-10): 제안 — `PUT /memorize/cursor { "plan_item_id": 123 }`로 마지막 카드를 저장한다. 저장 위치는 데이터 모델 v0.2에서 정한다 (§8).

## 6. 시험 API

시험 문제에 정답이 들어 있으면 브라우저에서 정답을 볼 수 있다. 그래서 **정답은 서버에만 두고** 클라이언트에는 문제와 보기만 보낸다.

| 메서드·경로 | 권한 | 설명 | 주요 규칙 |
|-------------|------|------|-----------|
| `POST /tests` | 인증 완료 | 시험 시작. 형식·방향·문항 수를 받아 문제를 만든다 | 본문: `{ "test_format", "test_direction", "count" }`. 문항 수는 단어 수와 설정값 중 작은 값 (설계 6.2). 단어가 부족하면 `422 TEST_NOT_POSSIBLE` |
| `GET /tests/{id}` | 로그인 | 진행 중인 시험 문제 조회 (새로고침 복원) | 정답·정답 번호는 빼고 응답 |
| `POST /tests/{id}/submit` | 인증 완료 | 답안 제출 | 본문: `{ "answers": [{ "item_id", "answer" }] }`. 객관식은 보기 번호, 주관식은 문자열. 채점은 서버에서 한다 (설계 6.3) |
| `GET /tests/history` | 로그인 | 시험 기록 목록 + 전체 정답률 | `limit`, `offset`. 정답률은 서버에서 계산 (D-19) |

- 시험 한 세트는 제출될 때 한 번만 기록된다 (D-15). 같은 시험을 두 번 제출하면 두 번째는 `409 TEST_ALREADY_SUBMITTED`.
- 제출 결과 응답: 문항별 정답 여부와 정답 (제출 후에만 정답을 보여준다), 총점. 오답이면 `study_records.wrong_count` +1 (D-11).
- 시험을 시작만 하고 제출하지 않으면 일정 시간(예: 24시간) 뒤 자동 폐기한다 (제안).

## 8. 데이터 모델 v0.2 반영 항목 (API 설계로 생긴 필요)

1. **신규 테이블 `test_attempts`**: 시험 시작 시 만든 문제 세트 (id, user_id, test_format, test_direction, status `open`/`submitted`/`expired`, created_at).
2. **신규 테이블 `test_attempt_items`**: 문항별 정답 정보 (attempt_id, position, word_id, direction, question, choices(JSON 또는 열 4개), correct_index, answers). 서버 내부용이며 조회 API에 노출하지 않는다.
3. **카드 위치 저장 위치**: `settings`에 열 추가(`memorize_cursor_item_id`)하는 안을 우선 검토한다. 별도 테이블은 과하다.
4. **`test_sessions`**: 제출 시 생성. `test_attempts.status`가 `submitted`로 바뀌는 것과 같은 트랜잭션.

## 9. 설계 결정 (ADR 형식)

### D-API01 REST JSON + `/api/v1` 경로
- **배경**: 화면이 브라우저 자바스크립트다. 자원 중심 URL이 권한 규칙을 이해하기 쉽다.
- **대안**: GraphQL (학습 규모에 비해 복잡), 화면 중심 RPC (재사용 어려움). 제외.

### D-API02 정답은 서버에만
- **근거**: 브라우저 개발자 도구로 정답을 볼 수 있으면 시험이 의미가 없다.
- **결과**: 시험 문제를 DB에 저장해야 한다 (§8-1, §8-2). 시험 한 번당 행 몇 개가 추가된다.

### D-API03 목록은 페이지 단위
- **근거**: 단어장은 수천 개다. 한 번에 다 보내면 느리다.
- **결과**: 검색·정렬도 서버 쿼리로 처리한다.

### D-API04 쓰기 요청은 인증 완료 회원만
- **근거**: 인증 설계 §3.4의 확정 사항 (쓰기는 인증 후에만).

### D-API05 암기 완료는 멱등
- **근거**: 네트워크 재시도나 중복 클릭으로 카운트가 두 번 오르면 기록이 틀린다.

### D-API06 단어 삭제는 목록(`POST /words/delete`)으로
- **대안**: `DELETE /words/{id}` 한 개씩. 기존 화면이 여러 개를 한 번에 지울 수 있어 목록 방식을 쓴다.
- **근거**: `DELETE`에 본문을 싣는 것은 일부 환경에서 막힌다.

### D-API07 API 문서 공개 여부 (제안)
- FastAPI의 자동 문서(`/docs`)는 개발 환경에서만 켠다. 공개 환경에서는 끈다 (구조 노출 최소화).
