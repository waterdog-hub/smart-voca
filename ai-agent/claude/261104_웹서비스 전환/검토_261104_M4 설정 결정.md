## 2. 주요 결정

표 전체는 이슈 #13에 있다. 되돌아볼 가능성이 큰 항목만 적는다.

### 숫자 칸의 최대값 9999
- **배경**: 설계는 최소값만 정했다. 상한이 없으면 DB 정수 한도를 넘는 값에서 드라이버 예외가 난다.
- **대안**: DB 정수 한도(2,147,483,647)까지 허용.
- **결정 근거**: 입력 오류로 끝내려면 어차피 상한이 필요하다. 21억이라는 안내 문구는 사용자에게 의미가 없다. 하루 9999개를 넘는 학습과 오답 기준은 실제로 쓰지 않는다. 설계에 없던 새 규칙이므로 문서에 추가한다.

### `current_day`와 카드 위치를 보내면 거절
- **배경**: API 설계 §4는 "클라이언트가 보낼 수 없다"고만 적었다. 무시와 거절이 모두 가능했다.
- **대안**: 알 수 없는 칸을 조용히 무시 (FastAPI 기본 동작).
- **결정 근거**: 잘못된 호출이 성공처럼 보이면 원인을 찾기 어렵다. 응답에도 두 값을 넣지 않아, 받은 값을 그대로 다시 보내는 화면이 거절당하지 않는다.

### 복습·오답·오답 기준에 DB CHECK를 추가하지 않음
- **배경**: `daily_new_count`만 DB에 CHECK가 있다. D-W15는 값이 정해진 문자열 열과 특정 관계를 다룬다.
- **대안**: 마이그레이션 0002로 세 열에 CHECK 추가 (CHECK 변경은 자동 생성되지 않아 직접 작성해야 함, D-IMP10).
- **결정 근거**: 세 값을 쓰는 경로는 `PUT /settings` 하나이고 서비스에서 검사한다. 쓰는 경로가 늘면 다시 검토한다.

### 서버가 규칙을 화면에 넘김
- **배경**: 화면 설계 §4.5는 저장 전에 칸 아래에 바로 안내하고 서버와 같은 규칙을 쓰라고 요구한다.
- **대안**: 자바스크립트에 최소값과 최대값을 복제.
- **결정 근거**: `setting_service.COUNT_FIELDS`로 칸을 그리고, 자바스크립트는 입력칸의 `min`, `max`를 읽는다. 규칙을 고칠 곳이 하나다.

## 3. `docs/web/`에 반영한 사항

| 문서 | 수정 |
|------|------|
| 요구사항 명세 | `FR-SET-01~03` 상태를 완료로. 추적 매트릭스의 구현 위치와 테스트 갱신. `FR-SET-02`에 최대값 9999 추가 |
| API 설계 | §4에 최소·최대값, 정수만 허용, 진도 칸을 보내면 400, 응답 칸 목록 추가 |
| 화면 설계 | §4.5에 최대값과 되돌리기 동작, 저장 안내 문구 추가 |
| 구현 계획 | M4 완료 표시, `static/` 설명에 설정 추가. 파일 구조는 저장소 파일을 하나씩 적지 않아 `setting_repository.py`는 넣지 않았다 |
| 테스트 정의 | 합계 272개, `test_settings_api.py` 25개, M4 완료 기준 결과, 브라우저 점검 항목 추가 |
| 데이터 모델 | §3.4에 범위는 서비스에서 검사한다고 명시 |
