## 4. 라이브 시연 시나리오 (2분)

발표 직전에 서버를 새로 띄우고, 시연 계정 하나를 미리 만들어 "초급 단어" 담기와 첫 일차 만들기까지 해 둔다 (그래야 시연이 가입 입력 없이 빠르다).

| 시각 | 동작 | 말할 내용 | 확인할 것 |
|------|------|-----------|-----------|
| 0:00 | 시작 화면에서 로그인 | "고양이 보카가 맞이합니다" | 노란 시연 안내띠 |
| 0:10 | 단어장 화면: "초급 단어" 담기 | "준비된 단어장을 골라 담으면 내 단어가 됩니다" | 담음 스티커 |
| 0:25 | 홈: "오늘의 티켓", [일차 만들기] → [이어서 암기하기] | "오늘 할 일을 자동으로 만들어 줍니다" | 진행 막대 |
| 0:40 | 암기: 뜻 보기 → 외움/다시 3장 (키보드 ↑ → ←) | "키보드로 빠르게 넘깁니다. 모르면 다시를 누르면 맨 뒤로 갑니다" | 버튼 |
| 1:10 | 시험: 객관식 3문항 → 제출 → 결과 표 | "서버가 채점하고, 틀린 단어는 다음 진도에 다시 나옵니다" | 결과 |
| 1:40 | 설정의 테마 색 바꾸기 → 더보기(휴대폰 화면) 보여 주기 | "색을 고를 수 있고 휴대폰에서도 같습니다" | 6색 |
| 1:55 | S4로 돌아오기 | | |

- **청중 참여**: 시연하는 동안 동기들이 S3의 주소로 접속해 가입해 볼 수 있다 (10명 이내, 시연 환경 한계). 시연자는 화면을 보이는 데 집중하고 참여 현황은 말하지 않는다.
- **시연에서 쓰지 않는 것**: 소셜 로그인(꺼져 있음), 비밀번호 재설정(메일 없음). 질문이 나오면 §6 답변을 쓴다.

## 6. 예상 질문과 답변

| 질문 | 답 |
|------|-----|
| 왜 웹으로 바꿨나? | 설치 없이 휴대폰과 PC에서 같은 학습 기록을 이어 쓰게 하려고 했다. 그래서 회원제와 서버 DB가 필요했다 |
| 단어는 어디서 가져왔나? 저작권은? | 프로젝트에 있던 표본 단어 목록(약 2천 개)을 500개씩 나눴다. 출처와 라이선스를 확인하지 못해서 시판 단어장은 넣지 않았다. 정식 공개 전에 출처를 확인할 계획이다 |
| 초급·중급·고급은 어떤 기준인가? | 목록 순서 기준이다. 앞 500개가 가장 기본적인 단어(the, be, to)이고, 뒤로 갈수록 주제가 섞여 있어 실제 난이도순은 아니다. 난이도 자료를 구하면 다시 나눌 수 있다 |
| 소셜 로그인은 실제로 되나? | 구현과 가짜 제공자 테스트까지 끝냈다. 구글·카카오 앱 등록이 필요해서 실제 확인은 아직이고, 시연에서는 끄고 했다 |
| 보안은 어떻게 했나? | 비밀번호는 argon2 해시만 저장하고, 로그인 실패는 횟수를 제한한다. 모든 데이터 조회에 회원 번호 조건을 걸고, 다른 회원 자원은 없는 것과 같은 404로 답한다(테스트 있음). 시험 정답은 제출 전에 내보내지 않는다 |
| 몇 명까지 쓸 수 있나? | 시연은 10명 이내로 잡았다. 부하 시험은 하지 않았다. 정식 공개 전에 PostgreSQL로 옮기고 확인할 계획이다 |
| 왜 ngrok인가? 배포한 건 아닌가? | 발표용으로 내 컴퓨터의 서버를 임시 주소로 열었다. 정식 배포는 호스팅(Render)과 메일(Resend)까지 정해 두었고 상용화 단계로 미뤘다 |
| AI는 무엇을 했고 본인은 무엇을 했나? | 무엇을 만들지, 어떤 방식을 택할지, 화면의 모양은 제가 정하고 승인했다. AI는 구현, 테스트, 문서 초안을 맡았다. 모든 변경은 제가 승인한 뒤에 커밋했다 |
| 테스트는 믿을 만한가? | 자동 테스트 546개로 규칙을, 실제 브라우저 점검 238개로 화면을, 실제 터널과 휴대폰으로 시연 흐름을 확인했다. 점검 중 실제로 버그 몇 개(탈퇴 오류 안내 누락, 휴대폰 표 깨짐 등)를 찾아 고쳤다 |
| 데스크톱 앱은 어떻게 되나? | 코드는 남아 있고 웹이 대체한다. 정리 여부는 아직 정하지 않았다 |
| 개인정보는? | 이메일과 접속 IP는 서버 키로 해시해서 비교하고, 탈퇴하면 회원 데이터를 즉시 삭제한다. 처리방침 문서는 공개 준비 단계에서 만든다 |
