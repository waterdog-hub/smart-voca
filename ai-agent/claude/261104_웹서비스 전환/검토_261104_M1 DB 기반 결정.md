## 1. 이슈 #8 제안에 더해 정한 사항

### 외래 키 삭제 방식
- **배경**: 데이터 모델은 "회원 삭제 시 함께 삭제"만 적었고, 다른 외래 키의 동작은 정하지 않았다.
- **대안**: 모든 외래 키에 CASCADE 적용, 서비스 코드에서 순서대로 삭제.
- **결정 근거**: 회원 소유 데이터의 `user_id`와 `test_attempt_items.attempt_id`만 CASCADE로 둔다. `word_id`는 기본 동작으로 두어 단어 행을 실수로 지우면 오류가 난다. 단어는 소프트 삭제가 규칙이고(D-W07), CASCADE를 쓰면 실수 한 번에 학습 기록이 사라진다. 회원 삭제는 한 문장 안에서 처리되어 이 기본 동작과 충돌하지 않는다 (SQLite 테스트로 확인).

### 추가 제약과 인덱스
- **배경**: 설계 문서에 명시된 제약만으로는 잘못된 값과 느린 조회를 막기 어렵다.
- **대안**: 서비스 코드에서만 검사.
- **결정 근거**: 값이 정해진 문자열 열에 CHECK를 둔다. `test_sessions.attempt_id`를 유일로 해 두 번 제출을 DB에서도 막는다. `auth_sessions`는 로그인 세션 또는 가입 대기 세션 중 하나만 되도록 CHECK를 둔다. PostgreSQL은 외래 키에 인덱스를 자동으로 만들지 않으므로 외래 키와 정리 작업용 열에 인덱스를 둔다.

### 문자열 길이
- **배경**: 데이터 모델은 "문자열"로만 적었다.
- **결정 근거**: 형식이 정해진 값에만 길이를 둔다 (해시 64자, 이메일 254자, 표시 이름 100자, 제공자 고유 번호 255자, 코드값). 단어와 뜻, 문제와 정답은 `Text`로 두고, 길이 제한은 M3 입력 검사에서 정한다. 표시 이름 100자는 설계에 없는 임시 값이므로 M2에서 입력 규칙과 맞춘다.

### `alembic.ini`는 영문만 사용
- **배경**: Alembic이 이 파일을 시스템 인코딩으로 읽어, 한글 주석이 있으면 한글 Windows(cp949)에서 `UnicodeDecodeError`가 난다.
- **대안**: `PYTHONUTF8=1` 환경변수 요구.
- **결정 근거**: 환경변수를 잊으면 실패하므로, 파일을 ASCII로 유지하는 쪽이 단순하다. CLAUDE.md의 한글 주석 관례보다 동작을 우선한다.

## 2. 설계 문서 수정 (2026-11-04 승인·반영)

아래 사항은 데이터 모델 v0.3(D-W14)과 구현 계획 v0.3에 반영했다.

| 위치 | 문제 | 제안 |
|------|------|------|
| 데이터 모델 v0.2 §4.4 | 삭제 순서가 `test_attempts` → `test_sessions`인데, `test_sessions`가 `test_attempts`를 참조한다. 이 순서대로 지우면 외래 키 오류가 난다 | `test_sessions`를 먼저 지운다고 고치거나, "회원 행 삭제 한 번으로 DB가 함께 삭제한다"로 바꾼다. 후자를 권장한다 (구현과 테스트가 이 방식) |
| 구현 계획 v0.2 §5 | M1 완료 표시가 없다 | M1 완료 표시, 실행 방식 `uvicorn --factory` 반영 |

## 3. 알려진 한계

- **PostgreSQL 미검증**: 테스트는 SQLite만 쓴다. PostgreSQL용 `CREATE TABLE`, `CREATE INDEX` 문장이 만들어지는 것만 확인했고, 실제 PostgreSQL에서 실행하지 않았다. 드라이버도 설치하지 않았다.
- **CHECK 변경 미감지**: `alembic check`는 CHECK 제약 변경을 감지하지 않는다. CHECK 이름을 바꿔도 통과하는 것을 확인했다. 열 추가는 감지한다. CHECK를 고칠 때는 마이그레이션을 직접 작성해야 한다.
