## 4. 아직 정하지 않은 항목

**사용자가 정할 것**
1. **설계 6종 검토**: 고칠 부분이 있으면 알려 주면 해당 문서를 수정한다. 검토가 끝나야 구현을 시작한다.
2. **운영 호스팅 업체 선정**: 요금, 한국 리전 유무, 백업 보관 기간을 공식 자료로 확인한 뒤 고른다 (배포 설계 D-OP07).
3. **도메인 구입**: 구입 후 `PUBLIC_BASE_URL`과 소셜 로그인 콜백 주소를 확정한다.
4. **소셜 로그인 앱 등록**: 구글, 카카오 개발자 콘솔에서 앱을 만들고 콜백 주소를 등록한다 (M8 전에 필요).
5. **데스크톱 앱 정리 시점** (구현 계획 M11): 웹 완성 후 제거할지, 함께 둘지.

**설계 문서에 남은 제안 값 (사용자 확인 또는 구현 중 조정)**
- 시험 도중 설정을 바꾸면 시작 시점 설정으로 채점할지 (API 설계 §10-1, 제안: 시작 시점)
- 제출하지 않은 시험 폐기 시간: 24시간 (API 설계 §10-2)
- 암기 카드 위치를 `settings` 열로 저장할지 (API 설계 §10-3)
- 시험 문항별 정답 기록 `test_answers` 테이블 추가 여부 (데이터 모델 §7-2, 보류)
- 휴대폰·데스크톱 화면 목업을 만들지 여부 (화면 설계 §9)
- 백업 보관 14일, RPO 24시간, RTO 4시간 (배포 설계 D-OP04, 제안 값)

## 7. 다른 PC에서 시작하는 절차 (Windows)

```
git clone https://github.com/waterdog-hub/smart-voca.git
cd smart-voca
git config core.autocrlf input
gh auth login
gh auth setup-git
py -3 -m unittest discover -s tests
```

- 필요한 프로그램: Python 3.14, Git, GitHub CLI(`gh`). 로그인 계정은 `waterdog-hub`.
- 기존 59개 테스트가 통과하면 준비 완료.
- Claude Code를 저장소 폴더에서 열고 다음처럼 시작한다.
  > "CLAUDE.md와 `ai-agent/claude/261104_웹서비스 전환/` 폴더의 인수인계 문서를 읽고 이어서 진행하자."

## 8. 주의 사항

- `core.autocrlf=input`은 `.git/config`에만 있어서 복제 후 다시 설정해야 한다.
- Claude 메모리와 대화 기록은 옮겨지지 않는다. 필요한 맥락은 이 문서와 설계 문서에 있다.
- `data/`, `.env`는 Git에서 제외되어 있다. 웹 전환은 새로 시작하므로 옮길 필요가 없다.
- 두 PC에서 동시에 작업하지 않는다. 시작 전 `git pull`, 끝나면 커밋과 push.
