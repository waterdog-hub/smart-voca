## 2. 확정된 방향 (사용자 답변)

| 항목 | 결정 |
|------|------|
| 백엔드 | FastAPI, 개발은 SQLite, 운영은 PostgreSQL |
| 로그인 | 이메일·비밀번호 + 구글·카카오 소셜 로그인 (네이버 제외) |
| 가입 후 | 인증 전에도 로그인 가능, 쓰기 기능은 인증 후에만 |
| 세션 | 절대 14일, 활동 없으면 3일 |
| 탈퇴 | 하드 삭제 (D-W12). 같은 이메일로 재가입 허용 |
| 이메일 | 모든 회원 필수. 소셜 가입에서 이메일이 없으면 입력 단계 거침 (D-W13) |
| 단어장 | 회원마다 자기 단어장 |
| 서비스 범위 | 공개 인터넷 서비스 |
| 데스크톱 앱 | 웹으로 대체 |
| 프런트엔드 | 서버 템플릿(Jinja2) + 필요한 부분만 자바스크립트 |
| 반응형 | 휴대폰 포함 전체 기능 지원 |
| 운영 호스팅 | 관리형 플랫폼 (업체는 미선정) |
| 도메인 | 새로 구입 필요 |
| 기존 데이터 | 옮기지 않고 새로 시작 |

## 4. 다음 할 일 (우선순위 순)

### 4.1 설계 2차 검토 반영 — 완료 (2026-11-04)
아래 항목은 모두 설계 문서에 반영하고 커밋했다 (`fff9b75`). 반영 위치는 각 문서의 변경 이력과 §5a(결정 기록)에 적었다.

**중간**
- 세션 종료 범위 통일: 비밀번호 변경 시 "전체 세션"(인증 설계 §2.1) vs "다른 세션"(API `POST /me/password`)
- CSRF 토큰 저장 열 추가: `auth_sessions`에 `csrf_token_hash` (데이터 모델 v0.2 §3.10)
- 요청 횟수 제한 범위 확장: 재설정 요청, `/me/password`, `DELETE /me`, 소셜 연결 확인 엔드포인트 (인증 설계 §5)
- OAuth state·PKCE verifier 저장 위치, 만료, 재사용 방지 명시 + 보안 테스트 항목 추가 (작업계획 §6)
- 기존 결정 변경 기록: 옛 D-06(문항마다 즉시 저장 → 제출 시 일괄), 옛 D-14(불러오기 덮어쓰기 → 추가), 옛 D-18(진도 불가 사유 → 409 단일 코드), 옛 D-10("다시" 누르면 같은 일차 맨 뒤로) → 결정 기록에 추가하고 API·데이터 모델에 규칙 명시
- 커서 저장 방식 확정: API 표에 `PUT /memorize/cursor` 엔드포인트 추가 또는 제거, `PUT /settings`가 커서 열을 덮어쓰지 않게 제외 (데이터 모델 v0.2 §3.4와 일치)
- 일차 생성 동시성: `POST /plans`는 `current_day` 조건부 갱신으로 같은 일차 중복 생성 방지
- 보관 기간 통일: login_attempts 30일 vs 접속 기록 90일, 학습 기록 보관 기간(결정 기록 §4-5) 처리방침 표에 추가

**낮음**
- API 오류 코드 표에 `LOGIN_FAILED`, `TOKEN_INVALID`, `LAST_LOGIN_METHOD` 추가, 잠금 시 응답 코드 확정
- 계정 단위 잠금의 DoS 취약성: IP와 계정 조합으로 판정 (데이터 모델 v0.2 §3.12에 방향 적어 둠, 인증 설계 §5.1 반영 필요)

## 5. 다른 PC에서 시작하는 절차 (Windows)

```
git clone https://github.com/waterdog-hub/smart-voca.git
cd smart-voca
git config core.autocrlf input
gh auth login
gh auth setup-git
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements-dev.txt
.venv\Scripts\python -m unittest discover -s tests
```

- 필요한 프로그램: Python 3.15, Git, GitHub CLI(`gh`). 로그인 계정은 `waterdog-hub`.
- 테스트 63개가 통과하면 준비 완료.
- Claude Code를 저장소 폴더에서 열고 다음처럼 시작한다.
  > "CLAUDE.md와 `ai-agent/claude/261104_웹서비스 전환/` 폴더의 인수인계 문서를 읽고, §4.4의 다음 마일스톤부터 이어서 진행하자."

## 6. 주의 사항

- `core.autocrlf=input`은 `.git/config`에만 있어서 복제 후 다시 설정해야 한다.
- Claude 메모리와 대화 기록은 옮겨지지 않는다. 필요한 맥락은 이 문서와 설계 문서에 있다.
- `data/`, `.env`, `.venv/`는 Git에서 제외되어 있다. 웹 전환은 새로 시작하므로 옮길 필요가 없다.
- 두 PC에서 동시에 작업하지 않는다. 시작 전 `git pull`, 끝나면 커밋과 push.
- 파일 수정, 커밋, push, 패키지 설치, 이슈 생성은 CLAUDE.md에 따라 사용자 승인 후에 한다.
