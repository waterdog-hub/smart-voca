## 2. 주요 결정

표 전체는 이슈 #14에 있다. 되돌아볼 가능성이 큰 항목만 적는다.

### 카드 위치 API를 만들지 않음 (사용자 확정)
- **배경**: API 설계는 `PUT /memorize/cursor`와 `settings.memorize_cursor_item_id`를 두었다. 그런데 화면은 항상 첫 번째 미완료 카드를 보여 주고, 외움은 `done`, 다시는 `position`으로 서버에 저장된다. 커서 값은 항상 이 카드와 같다.
- **대안**: 설계대로 구현 (카드마다 요청이 늘고 상태가 둘이 됨), 열까지 삭제 (마이그레이션과 외래 키 변경 필요).
- **결정 근거**: 데스크톱 D-10도 순서로만 복원한다. 카드를 건너뛰는 기능이 생기면 다시 검토한다. 열은 미사용으로 남긴다.

### 지난 일차 복습 허용, 기록은 바꾸지 않음
- **배경**: 화면 설계 M-01의 드롭다운과 D-16의 읽기 전용이 충돌했다. 사용자가 드롭다운으로 복습을 허용하기로 했고, 기록을 바꾸지 않는 규칙도 확인했다.
- **대안**: 복습에서도 `memorized_count`와 날짜를 갱신.
- **결정 근거**: 복습은 화면 안에서만 진행하고 저장하지 않는다. `done`, `position`, 진행률, 다음 일차의 복습 후보가 바뀌지 않아 D-16을 지킨다. 지난 일차의 `PATCH`는 `409 PLAN_ITEM_NOT_CURRENT`다. 새로고침하면 복습은 처음부터 시작한다.

### 오늘 날짜는 고정 UTC+9
- **배경**: `last_memorized_date`는 한국 날짜여야 한다 (D-W11). `zoneinfo`는 Windows에서 `tzdata` 패키지가 더 필요하다.
- **대안**: `tzdata` 추가, 서버 시간 사용 (운영 서버가 UTC면 날짜가 틀림).
- **결정 근거**: 한국은 서머타임이 없어 고정값으로 충분하고 패키지가 늘지 않는다.

### 로그인 후 복귀는 브라우저 파서로 주소 검사
- **배경**: `/login?next=`는 검사하지 않으면 외부 사이트로 보내는 데 악용된다. `//evil.example`, `/\evil.example`처럼 문자열 검사를 빠져나가는 형식이 있다.
- **대안**: 문자열 접두어 검사, 복귀 없이 문서만 수정.
- **결정 근거**: `new URL()`로 해석한 출처가 같을 때만 따른다. 브라우저가 실제로 이동할 주소를 기준으로 판단한다. 위 형식과 `javascript:`를 실제 브라우저로 확인했다.

## 3. 구현 중 발견한 결함 (수정 완료)

| 결함 | 발견 방법 | 수정 |
|------|-----------|------|
| `{"done": 1}`이 외움으로 기록됨 (`Literal[True]`가 1을 허용) | 자동 테스트 | `StrictBool` 사용 |
| 카드를 다 외워도 다음 일차 버튼이 숨겨진 채로 남음 | 브라우저 점검 | 요약 안에서 항상 표시 |
| 뜻을 보기 전에 외움·다시 버튼이 보임 (`display: flex`가 `hidden`을 덮어씀) | 스크린샷 확인. 자동 점검은 속성만 봐서 통과했음 | `[hidden] { display: none !important; }`, 점검을 실제 표시 기준으로 변경 |
