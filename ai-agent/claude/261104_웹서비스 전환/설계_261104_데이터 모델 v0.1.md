## 1. 전제

- 결정 기록 v0.1 (`설계_261104_웹 전환 결정 기록 v0.1.md`)의 확정 사항을 따른다.
  - 백엔드 FastAPI, 저장소 SQLite로 시작 후 PostgreSQL 전환 (D-W02)
  - 단어장은 회원마다 따로 보관 (D-W06)
- 기존 규칙을 유지한다: 단어 삭제 시 학습 기록 유지 (D-09, D-12), 단어 이름 변경 시 기록·진도 동기화 (D-13), 같은 단어는 대소문자 무시 중복 (D-24), 시험마다 오답 집계 (D-11).
- 설계는 테이블·컬럼·제약 수준까지만 쓴다. SQL 코드는 구현 단계에서 쓴다 (CLAUDE.md 문서 규칙).
- 모든 기본 키는 정수 자동 증가(`id`)로 둔다. PostgreSQL 전환 때 그대로 옮길 수 있는 타입만 쓴다.

## 2. 테이블 목록

| 테이블 | 역할 | 기존 CSV 대응 |
|--------|------|---------------|
| `users` | 회원 계정 | 없음 (신규) |
| `social_accounts` | 소셜 로그인 연결 (2단계 인증에서 사용) | 없음 (신규) |
| `words` | 회원별 단어장 | `words.csv` |
| `settings` | 회원별 설정 한 벌 | `settings.csv` |
| `study_records` | 단어별 암기·오답 기록 | `study_record.csv` |
| `plan_items` | 일차별 진도 한 줄 | `day_plan.csv` |
| `test_sessions` | 시험 한 세트의 결과 | `test_history.csv` |

인증 세션, 이메일 인증 토큰, 비밀번호 재설정 토큰은 3단계(인증·보안 설계)에서 정한다.

## 3. 테이블 상세

### 3.1 `users` (회원)

| 열 | 타입 | 필수 | 설명 |
|----|------|------|------|
| id | 정수 | O | 기본 키 |
| email | 문자열 | O | 로그인 아이디. 대소문자 무시 유일 (저장 시 소문자로 정규화) |
| password_hash | 문자열 | X | 비밀번호 해시. 소셜 전용 계정이면 비움 |
| display_name | 문자열 | O | 화면 표시 이름 |
| email_verified_at | 일시 | X | 이메일 인증 완료 시각 (인증 방식은 열린 질문) |
| created_at | 일시 | O | 가입 시각 |
| deleted_at | 일시 | X | 탈퇴 표시 (탈퇴 처리 방식은 열린 질문) |

- `email`에 유일 제약을 둔다. 탈퇴한 회원의 이메일 재사용 정책은 탈퇴 방식이 정해진 뒤 정한다.

### 3.2 `social_accounts` (소셜 연결)

| 열 | 타입 | 필수 | 설명 |
|----|------|------|------|
| id | 정수 | O | 기본 키 |
| user_id | 정수 | O | `users.id` (회원 삭제 시 함께 삭제) |
| provider | 문자열 | O | 제공자 이름 (예: `google`) |
| provider_user_id | 문자열 | O | 제공자 쪽 사용자 고유 번호 |
| created_at | 일시 | O | 연결 시각 |

- `(provider, provider_user_id)`는 유일해야 한다. 같은 소셜 계정이 두 회원에 붙지 않게 한다.
- 소셜 로그인 때 이메일이 같은 기존 회원이 있으면 이 테이블에 연결만 추가한다 (결정 기록 D-W03 제안).

### 3.3 `words` (회원별 단어장)

| 열 | 타입 | 필수 | 설명 |
|----|------|------|------|
| id | 정수 | O | 기본 키. 단어 이름이 바뀌어도 바뀌지 않음 |
| user_id | 정수 | O | `users.id` |
| word | 문자열 | O | 표시용 영문 단어 (공백 제거 후 저장, 대소문자 원형 유지) |
| word_key | 문자열 | O | 중복 판정용 소문자 단어 (`word`를 소문자로 바꾼 값) |
| meaning | 문자열 | O | 한글 뜻, 여러 개면 `/` 구분 (CSV와 같은 형식) |
| deleted_at | 일시 | X | 삭제 표시 (소프트 삭제, §4.1) |
| created_at | 일시 | O | 등록 시각 |
| updated_at | 일시 | O | 마지막 수정 시각 |

- 유일 제약: `(user_id, word_key)`는 **삭제되지 않은 행끼리만** 유일해야 한다 (부분 유일 인덱스). D-24 규칙을 DB에서도 지킨다.
- `meaning`을 별도 테이블로 쪼개지 않는다. 기존 CSV와 같은 `/` 형식을 유지해 `Word.meaning_list` 변환 로직을 그대로 쓴다.

### 3.4 `settings` (회원별 설정)

| 열 | 타입 | 필수 | 설명 |
|----|------|------|------|
| user_id | 정수 | O | 기본 키이자 `users.id` (회원 한 명당 한 행) |
| daily_new_count | 정수 | O | 기본 20, 1 이상 (D-23) |
| daily_review_count | 정수 | O | 기본 5 |
| daily_wrong_count | 정수 | O | 기본 5 |
| wrong_threshold | 정수 | O | 기본 3 |
| test_format | 문자열 | O | `multiple` / `subjective` |
| test_direction | 문자열 | O | `en_ko` / `ko_en` / `both` |
| current_day | 정수 | O | 마지막으로 생성된 일차 (0이면 진도 없음). 기존 설정 항목 유지 |

- 회원 가입 때 기본값 한 행을 만든다.
- 허용 값과 최소값은 DB 검사 제약과 서비스 계층 검증 두 곳에서 확인한다.

### 3.5 `study_records` (단어별 암기·오답 기록)

| 열 | 타입 | 필수 | 설명 |
|----|------|------|------|
| user_id | 정수 | O | `users.id` |
| word_id | 정수 | O | `words.id` (소프트 삭제 때문에 행이 남으므로 기록도 남는다) |
| memorized_count | 정수 | O | 암기 완료 누적 횟수, 기본 0 |
| first_memorized_day | 정수 | O | 처음 외운 일차 (0이면 미암기) |
| last_memorized_date | 날짜 | X | 마지막 암기 날짜 |
| wrong_count | 정수 | O | 시험 오답 누적 횟수, 기본 0 |
| last_wrong_date | 날짜 | X | 마지막 오답 날짜 |

- 기본 키: `(user_id, word_id)`.
- 단어 등록 시 기본 행(0, 빈 날짜)을 만든다. 기존 CSV의 "단어 목록을 새로 불러오면 기본 행 생성" 규칙과 같다.

### 3.6 `plan_items` (일차별 진도)

| 열 | 타입 | 필수 | 설명 |
|----|------|------|------|
| id | 정수 | O | 기본 키 |
| user_id | 정수 | O | `users.id` |
| day | 정수 | O | 일차 번호 (1부터) |
| word_id | 정수 | O | `words.id` |
| assigned_type | 문자열 | O | `new` / `review` / `wrong` |
| done | 불리언 | O | 암기 완료 여부 (기본 거짓) |
| position | 정수 | O | 같은 일차 안의 순서. 암기 카드 위치 복원에 쓴다 (D-10) |

- 유일 제약: `(user_id, day, word_id)` — 같은 일차에 같은 단어가 두 번 들어가지 않는다.
- 인덱스: `(user_id, day)` — 일차별 조회용.
- 단어 소프트 삭제 때는 **해당 단어의 `plan_items` 행을 같은 트랜잭션에서 지운다** (D-12). `position` 빈 칸은 메우지 않는다 (기존 CSV 동작과 같다).

### 3.7 `test_sessions` (시험 결과)

| 열 | 타입 | 필수 | 설명 |
|----|------|------|------|
| id | 정수 | O | 기본 키 |
| user_id | 정수 | O | `users.id` |
| taken_at | 일시 | O | 시험 완료 시각 |
| test_format | 문자열 | O | `multiple` / `subjective` |
| test_direction | 문자열 | O | `en_ko` / `ko_en` / `both` |
| total | 정수 | O | 문항 수 |
| score | 정수 | O | 정답 수 (`score <= total` 검사) |

- 인덱스: `(user_id, taken_at)` — 최근 순 목록용.
- 정답률은 저장하지 않고 조회 때 계산한다 (기존 `accuracy_percent()` 동작 유지).

## 4. 규칙 대응

### 4.1 단어 삭제 — 소프트 삭제 (D-09, D-12 유지)

- 단어 삭제 시 `words.deleted_at`만 채운다. 행은 남기므로 `study_records`가 살아 있다.
- 같은 트랜잭션에서 `plan_items`의 해당 행을 지운다.
- 삭제된 단어는 목록·검색·진도 생성에서 제외한다 (조회 조건 `deleted_at IS NULL`).
- 같은 단어를 다시 추가하면 삭제된 행을 되살린다 (`deleted_at`을 지우고 뜻 갱신). 이전 기록이 이어진다. 기존 CSV에서 단어를 다시 넣었을 때 기록이 살아 있던 동작과 같다.

### 4.2 단어 이름 변경 (D-13)

- `words.id`가 그대로이므로 `study_records`와 `plan_items`를 고칠 필요가 없다.
- `word`와 `word_key`만 바꾼다. 바꾼 이름이 다른 단어와 겹치면 중복으로 거절한다 (D-24).

### 4.3 CSV 불러오기 (D-14, D-22)

- 불러오기 한 번을 한 트랜잭션으로 묶는다. 중간에 실패하면 전부 되돌린다.
- 같은 `word_key`가 살아 있으면 건너뛰고 개수를 알린다 (첫 항목만 유지, D-24).
- 불러오기 전 백업은 DB 덤프 또는 기존 CSV 내보내기로 대신한다 (백업 정책은 배포 설계에서 정한다).

### 4.4 시험 오답 집계 (D-11)

- 시험 문항마다 `study_records.wrong_count`를 1 올린다. 같은 날 여러 번 시험을 보면 시험마다 집계한다.
- 제안(미확정): 문항별 정답 여부를 `test_answers` 테이블에 남기면 나중에 "자주 틀린 단어" 분석이 쉬워진다. 지금은 넣지 않는다 (YAGNI). 필요해질 때 추가한다.

## 5. 기존 CSV → DB 이관 대응

| CSV | 열 | DB | 변환 |
|-----|-----|----|------|
| words.csv | word | words.word, word_key | `word_key` = 소문자 값 |
| words.csv | meaning | words.meaning | 그대로 |
| settings.csv | key/value 쌍 | settings 한 행 | 항목을 열로 펼침, 값이 틀리면 기본값 (D-05) |
| study_record.csv | word | study_records.word_id | `words`에서 `word_key`로 찾아 연결. 없으면 건너뜀 |
| day_plan.csv | day, word, assigned_type, done | plan_items | `word`를 `word_id`로 바꾸고 파일 순서를 `position`으로 |
| test_history.csv | 각 열 | test_sessions | `taken_at`을 일시로 변환 |

- 이관은 한 명의 회원 계정으로 로그인한 상태에서 한 번 실행하는 기능으로 본다. 구체적 흐름은 구현 계획 단계에서 정한다.

## 6. 설계 결정 (ADR 형식)

### D-W07 단어 삭제는 소프트 삭제
- **배경**: 기존 결정 D-09, D-12는 "단어를 지워도 학습 기록은 남긴다"이다. 행을 실제로 지우면 `study_records`가 함께 사라진다 (외래 키 연쇄 삭제).
- **대안**: (a) 하드 삭제 후 기록을 단어 문자열로 따로 보관, (b) 소프트 삭제 (채택).
- **결정 근거**: (b)는 `word_id`로 연결을 유지해 이름 변경(D-13)도 그대로 처리된다. 한 행만 살려 두면 되므로 규칙이 단순하다.
- **비용**: 유일 제약에 부분 인덱스가 필요하다. PostgreSQL에서도 지원된다.

### D-W08 기록과 진도의 연결 키는 `word_id`
- **배경**: 기존 CSV는 단어 문자열을 키로 썼다. 이름 변경 때 여러 파일을 고쳐야 했다.
- **결정**: 모든 자식 테이블은 `word_id`로 연결한다. 이름 변경 때 자식 테이블을 건드리지 않는다.

### D-W09 설정은 회원당 한 행
- **배경**: 기존 설정 파일은 key/value 여러 줄이다.
- **대안**: key/value 테이블 유지 (스키마 변경 없음, 검증이 약함).
- **결정 근거**: 열로 펼치면 타입과 검사 제약을 DB에서 걸 수 있다. 설정 항목이 7개로 고정돼 있어 펼쳐도 불편이 없다.

### D-W10 `current_day`는 저장값으로 유지
- **배경**: 기존 설정에 있는 값이고, 최대 일차 `MAX(day)`로 계산할 수도 있다.
- **대안**: `plan_items`에서 계산 (저장값 없음).
- **결정(잠정)**: 기존 동작을 그대로 옮기도록 저장한다. 단, 진도가 없을 때 0이어야 한다는 규칙을 구현 테스트에 넣는다. 불일치가 생기면 계산 방식으로 바꾼다.

### D-W11 시각 값
- **결정**: 일시는 UTC로 저장하고, 화면에는 한국 시간으로 보여준다. 기존 `taken_at` 문자열(YYYY-MM-DD HH:MM)은 이관할 때 한국 시간을 기준으로 변환한다.
- **근거**: 서버 위치와 무관하게 시각이 맞게 하기 위해서다. 한국 서비스라 표시는 KST로 고정한다.
