# MW 공용 단어장 결정

**파일 위치**: `ai-agent/claude/261104_웹서비스 전환/검토_261105_MW 공용 단어장 결정.md`
**작성일**: 2026-11-05
**버전**: v0.2
**설명**: 회원이 단어를 직접 추가·수정·삭제하고 CSV로 저장하던 방식을, 운영자가 준비한 공용 단어장을 고르는 방식으로 바꾸는 결정과 이유를 기록한다. 결정 표 전체는 GitHub 이슈에 있다

---

## 1. 배경

- M3에서 만든 단어장은 회원이 단어를 하나씩 입력하거나 CSV 파일을 올려 자기 단어장을 만드는 방식이다 (`FR-WORD-01~05`, `09~12`).
- 사용자 요청 (2026-11-05): 직접 추가·삭제와 CSV 저장 대신, 다른 사전이나 수능 영어단어 같은 단어장을 가져오는 방식으로 바꾼다.
- 사용자 답변: 공용 단어장 목록에서 고른다. 직접 추가·수정은 없애고 담은 단어장 제외만 허용한다. CSV 가져오기는 운영자 전용, 내려받기는 제거한다.
- 웹은 이미 CSV가 아니라 DB(`words` 테이블)에 저장한다. CSV 저장은 데스크톱 앱의 방식이고, 웹의 CSV는 가져오기와 내려받기뿐이다.

## 2. 결정

### D-WB01 공용 단어장은 운영자가 넣는 읽기 전용 목록
- **배경**: 지금은 모든 단어가 `words.user_id`로 회원에 묶여 있어 여러 회원이 함께 고를 수 있는 단어장이 없다.
- **대안**: 외부 사전 API 검색 (영어 뜻만 주고 한글 뜻은 따로 번역해야 하며, 시연 중 외부 서비스에 의존). Quizlet 같은 서비스의 파일 가져오기 (회원이 파일을 직접 구해야 함).
- **결정 근거**: 시연에 인터넷 연결이 필요 없고, 한글 뜻을 가진 단어장을 바로 보여 줄 수 있다. 새 테이블 3개 `wordbooks`, `wordbook_entries`, `user_wordbooks`를 둔다.

### D-WB02 담기는 회원의 `words`로 복사
- **배경**: 일차 진도(`plan_items`), 학습 기록(`study_records`), 시험이 모두 `words.id`에 묶여 있다.
- **대안**: 단어장 항목을 직접 참조 (진도, 기록, 시험 테이블과 코드를 모두 바꿔야 함).
- **결정 근거**: M5, M6 코드를 바꾸지 않는다. 회원 간 격리(D-A09)도 그대로다. 단점은 운영자가 단어장 내용을 고쳐도 이미 담은 회원의 단어는 바뀌지 않는다는 것이다 (알려진 위험).

### D-WB03 제외는 다른 담은 단어장에 없는 단어만 소프트 삭제
- **배경**: 같은 단어(`the`)가 두 단어장에 있을 수 있다.
- **대안**: 단어장 단위로 제외하면 항상 전부 삭제 (남은 단어장의 단어가 사라짐).
- **결정 근거**: 남은 단어장에 있는 단어는 유지한다. 지운 단어는 기존 소프트 삭제(D-W07)라 학습 기록이 남고, 다시 담으면 기록을 이어 간다 (`FR-WORD-05`).

### D-WB04 회원의 직접 추가·수정·삭제, CSV 가져오기·내려받기를 제거
- **배경**: 사용자 결정.
- **대안**: 화면에서만 숨기기 (안 쓰는 API가 남아 공격 면이 된다). 내려받기 유지.
- **결정 근거**: `POST /words`, `PATCH /words/{id}`, `POST /words/delete`, `POST /words/import`, `GET /words/export`와 관련 코드·테스트를 지운다. `GET /words`(검색, 정렬, 페이지)는 "내 단어" 조회용으로 남긴다 (`FR-WORD-06~08`).

### D-WB05 단어장 등록은 운영자 명령줄 도구
- **배경**: 계정에 관리자 권한 개념이 없다.
- **대안**: 관리자 화면 (권한 설계, 업로드 보안, 화면이 모두 새로 필요).
- **결정 근거**: `ai-agent/scripts/load_wordbooks.py`가 `data/wordbooks.json`에 적힌 CSV를 읽어 DB에 넣는다. 같은 `slug`로 다시 실행하면 항목을 통째로 바꾼다. 로직은 `web/services/wordbook_loader.py`에 두어 자동 테스트한다.

### D-WB06 같은 단어는 먼저 담은 뜻을 유지
- **배경**: 단어장마다 같은 단어의 뜻이 다를 수 있다.
- **결정 근거**: 회원이 이미 가진 단어는 건드리지 않고 건너뛴다. 뜻이 바뀌면 학습 중인 단어의 뜻이 달라지는 혼란을 막는다.

### D-WB07 담기·제외도 이메일 인증이 필요
- **결정 근거**: 회원 데이터를 바꾸는 API이므로 `VerifiedWrite`를 붙인다 (CLAUDE.md 새 쓰기 API 규칙).

### D-WB08 화면은 단어장(`/wordbooks`)과 내 단어(`/words`)로 나눔
- **배경**: 한 화면에 고르기와 보기를 섞으면 어느 쪽 화면인지 흐려진다.
- **결정 근거**: `/wordbooks`는 단어장 카드 목록과 담기·제외 버튼, `/words`는 읽기 전용 목록이다. 메뉴는 "단어장", "내 단어" 순서다.

### D-WB09 샘플 단어장은 `data/words.csv`를 구간으로 나눠 사용
- **배경**: 저장소에 있는 표본 1,988개가 빈도순으로 정렬돼 있다.
- **결정 근거**: 파일을 복사하지 않고 `data/wordbooks.json`에 구간(행 범위)을 적어 4개 단어장으로 나눈다. 이름은 "기본 영단어 1~4"로 하고 수능 같은 이름을 붙이지 않는다. 출처가 확인된 자료만 그 이름으로 추가한다.

### D-WB10 기존 회원 단어는 변환하지 않음
- **배경**: 운영 전이고 시연 DB는 시연마다 새로 만든다.
- **결정 근거**: 마이그레이션은 새 테이블만 만들고 `words`를 건드리지 않는다.

## 4. 알려진 위험

- 운영자가 단어장 내용을 고쳐도 이미 담은 회원의 단어에는 반영되지 않는다. 필요해지면 "다시 담기"로 뜻을 갱신하는 기능을 검토한다.
- `data/words.csv`의 출처와 라이선스를 확인하지 못했다. 공개 저장소에 올라가 있으므로 실제 서비스 전에 확인이 필요하다. 시판 수능 단어장은 저작권이 있어 허락 없이 넣지 않는다.
- 담기·제외에 요청 횟수 제한이 없다. 반복해도 행이 늘지 않아(소프트 삭제 행을 되살림) 저장 공간은 문제없지만 처리 시간은 든다. M10 공개 준비에서 검토한다.
- 직접 만든 단어가 없어졌으므로 단어장에 없는 단어는 학습할 수 없다.

## 5. 구현 중 추가한 결정

### D-WB11 담기에서 조회를 쓰기 전에 모두 끝냄
- **배경**: 같은 회원의 동시 요청이 겹치면 유일 제약 오류가 `commit`이 아니라 그 앞의 자동 flush에서 날 수 있다. 처음 구현은 쓰는 중에 조회(`has_user_wordbook`)를 해서 오류가 `try` 밖에서 나 500이 됐다. 경쟁 상황을 재현한 테스트(`test_losing_a_race_changes_nothing_and_returns_409`)가 잡았다.
- **결정 근거**: 조회를 쓰기 앞으로 모으고 `commit`만 `try`로 감싸 `409 WORDBOOK_BUSY`로 바꾼다. 일부만 저장하지 않고 전체를 되돌린다.

### D-WB12 웹 테스트의 단어는 DB에 직접 넣음
- **배경**: 진도와 시험 테스트 다수가 단어 추가·삭제·수정 API로 단어를 준비했다.
- **결정 근거**: `AuthTestCase.insert_words`, `delete_words`, `insert_wordbook`을 두고 바꿨다. 이름 변경은 더 이상 일어날 수 없어 `FR-WORD-03` 관련 테스트는 지웠다. 시험과 진도 코드는 그대로이며 같은 테스트가 통과한다.

### D-WB13 브라우저 점검은 운영자 도구로 단어장을 넣음
- **결정 근거**: 서버를 띄우기 전에 `load_wordbooks.py`로 표본 단어장과 점검용 작은 단어장 4개를 임시 DB에 넣는다. 점검 파일은 화면에서 "담기"를 눌러 단어를 준비하므로 실제 사용 흐름까지 함께 확인된다. 시연 서버(`demo_server.py start`)도 시작할 때 같은 도구를 실행한다.

### 정리한 것
- `csv_guard.py`의 `neutralize_formula`, `restore_formula_prefix`, `MAX_IMPORT_ROWS`, `rate_limit.py`의 `ACTION_IMPORT`, `IMPORT_PER_ACCOUNT`는 쓰는 곳이 없어 지웠다. 내려받기와 회원 가져오기가 없어 수식 주입 경로도 사라졌다.
- 단어 검증 규칙(`find_word_problems`, `normalize_meaning`)은 `wordbook_loader.py`로 옮겼다.
