## 2. 주요 결정

표 전체는 이슈 #15에 있다. 되돌아볼 가능성이 큰 항목만 적는다.

### 미응답 문항은 점수에서 오답, 오답 기록은 올리지 않음 (사용자 확정)
- **배경**: 데스크톱은 문항마다 답해야 다음으로 넘어가 미응답이 없었다. 웹은 답을 비운 채 제출할 수 있다. API 설계는 "오답이면 `wrong_count` +1"만 적었다.
- **대안**: 미응답도 오답과 같이 `wrong_count`에 집계.
- **결정 근거**: 풀지 않은 단어는 틀렸다는 증거가 아니다. 200문항 시험을 3번에서 그만두고 제출하면 197개가 오답 대상이 되어 다음 진도가 왜곡된다. 점수에는 오답으로 넣어 정답률은 정직하게 보여 준다.

### 답안은 제출 때만 서버로 보냄
- **배경**: 화면 설계는 새로고침 복원을 요구한다. 문제는 서버에 있지만 답안 저장 테이블(`test_answers`)은 보류 상태다.
- **대안**: 문항마다 서버 저장 (테이블 추가, 요청 증가).
- **결정 근거**: 답안은 `sessionStorage`에 둔다. 같은 탭의 새로고침과 세션 만료 후 복귀에서 복원된다. 탭을 닫거나 다른 기기로 옮기면 문제만 복원되고 답은 사라진다.

### 문항별 결과는 제출 응답으로만 제공
- **배경**: 답안을 저장하지 않으므로 나중에 "내 답"을 보여 줄 수 없다.
- **대안**: `test_answers` 추가.
- **결정 근거**: 데이터 모델 §7의 보류를 유지한다. 제출한 시험을 다시 열면 점수만 보여 준다. 분석 기능이 필요해지면 테이블을 추가한다.

### 폐기는 조회와 제출 때 판단
- **배경**: 미제출 시험은 24시간 뒤 폐기한다. 예약 작업 기반이 아직 없다.
- **대안**: 주기 작업으로 상태 변경.
- **결정 근거**: `expires_at`을 조회·제출 때 비교해 `409 TEST_EXPIRED`로 처리한다. 새 시험을 시작하면 남은 `open`을 `expired`로 바꾼다. 쌓인 행의 정리는 M10에서 다룬다.

### 문항 수는 요청값 1~200
- **배경**: API 설계는 "단어 수와 설정값 중 작은 값"이라 했지만 설정에 문항 수 칸이 없다.
- **대안**: 설정에 칸 추가 (스키마 변경).
- **결정 근거**: 데스크톱과 같이 시험을 시작할 때 고른다. 기본 10, 최대 200이고 단어 수보다 크면 단어 수만큼 낸다.
