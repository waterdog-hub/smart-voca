## 2. 주요 결정

표 전체는 이슈 #10에 있다. 되돌아볼 가능성이 큰 항목만 적는다.

### core의 `validate`, `filter_by_keyword`를 호출하지 않음
- **배경**: 구현 계획 §2.1은 "검증·검색 규칙은 그대로 호출"로 적었다. 두 함수는 단어 전체를 메모리에 올려야 한다.
- **대안**: 요청마다 단어 전체를 읽어 그대로 호출. 수천 개 단어에서 느리고, 동시 요청의 중복은 어차피 막지 못한다.
- **결정 근거**: API 설계 D-API03이 검색·정렬의 서버 쿼리를 요구한다. 중복은 조회와 부분 유일 인덱스로 처리하고, 규칙(소문자 키, 대소문자 무시 검색)은 같게 유지한다. `split_meanings`와 빈 값 검사는 그대로 호출한다.

### 내보내기 수식 방지를 가져오기에서 되돌림
- **배경**: 내보낼 때 `'`를 붙이기만 하면 내보낸 파일을 다시 가져올 때 `-ing`가 `'-ing`으로 바뀐다. 웹에는 서버 백업 대신 내보내기가 회원의 백업 수단이다 (결정 기록 §5a).
- **대안**: 내보낼 때만 처리 (왕복이 깨짐), 처리하지 않음 (공격 위험).
- **결정 근거**: 가져올 때 접두를 하나 제거한다. 원래 `'=`로 시작하는 값은 내보낼 때 `'`를 하나 더 붙여 왕복을 보존한다.

### 가져오기에 CP949 허용
- **배경**: 한글 Excel의 기본 CSV 저장은 CP949다. 데스크톱은 `utf-8-sig`만 읽었다.
- **결정 근거**: 공개 웹 사용자는 Excel에서 바로 저장해 올릴 가능성이 높다. UTF-8을 먼저 시도하므로 기존 파일 동작은 같다.

### 뒤 열에 값이 있는 행은 형식 오류
- **배경**: 데스크톱은 3번째 열 이후를 버렸다. `run,달리다, 뛰다`의 뜻이 조용히 `달리다`로 잘린다.
- **결정 근거**: 데이터가 조용히 사라지는 것보다 줄 번호로 알리는 편이 낫다. 뒤 열이 비어 있으면 Excel이 만든 빈 열이므로 허용한다.

## 4. 검증 기록

- 자동 테스트: 247개 통과 (기존 174개 + M3 73개).
- 마이그레이션: 빈 DB에 적용 후 `alembic check` 변경 없음.
- 브라우저 점검: 임시 DB, 실제 uvicorn, 헤드리스 Chrome으로 39개 항목 통과. 표본 단어장 `data/words.csv` 1,988개를 실제로 가져옴 (약 0.3초). 원본 파일은 읽기만 했다. 회원 틀을 바꿨으므로 M2 흐름 20개 항목도 다시 통과를 확인했다.
- 스크린샷 확인에서 발견해 고친 결함 2건: (1) 데스크톱 폭에서 메뉴가 긴 목록 높이만큼 늘어나 로그아웃 버튼이 페이지 맨 아래로 밀렸다. 메뉴를 화면 높이에 고정했다. (2) 휴대폰 폭의 짧은 화면에서 메뉴와 본문 사이가 벌어졌다. 그리드 줄 높이를 지정했다.
